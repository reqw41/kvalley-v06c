# OldTower (Денис Грачёв, 2023) — разбор движка Вектор-06Ц
Исходник: github.com/DenisGrachev/OldTowerVector06c (клон в /tmp/oldtower, main.asm + include/*.a80).
Цель: перенять техники для всех наших Вектор-проектов (kvalley, knightmare, monty).

## 1. POP-движок тайлов/спрайтов — сердце скорости (sprites.a80)
Тайл 8×8 рисуется В ЧЕТЫРЕ ПЛОСКОСТИ (16 цветов!) за ~15 инстр/строку:
```
    ld sp,hl        ; SP = АДРЕС ДАННЫХ тайла (di перед этим!)
    ex de,hl        ; HL = адрес в кадровом буфере
    ld bc,32*256+32*3   ; B=0x20 (шаг плоскости!), C=0x60 (откат)
    ; строка (×8, unrolled):
    pop de              ; 2 байта данных за 11 тактов
    ld (hl),e : add b : ld h,a   ; плоскость 0 → H+=0x20 → плоскость 1
    ld (hl),d : add b : ld h,a   ; плоскость 1 → 2
    pop de
    ld (hl),e : add b : ld h,a   ; плоскость 2 → 3
    ld (hl),d                    ; плоскость 3
    sub c : ld h,a               ; H-=0x60 (назад в плоскость 0)
    dec l                        ; строка ниже
```
КЛЮЧИ: (а) данные тайла хранятся **interleaved по плоскостям** (p0,p1,p2,p3 построчно)
— формат подготовлен конвертером на PC (res/: PNG→.tiles); (б) шаг между плоскостями
Вектора = +0x20 в СТАРШЕМ байте (add b/ld h,a = 2 такта!); (в) POP = самое быстрое
чтение 8080. Итого полноцветный тайл ≈ 120 инстр — наш 1-плоскостный блит стоит 68!

## 2. Развёрнутый код + вычисляемый вход (partial draw)
Блок строки продублирован `dup 8` и выровнен на страницу (`org ($+255)&0xFF00`).
Для обрезанных тайлов (верх/низ экрана при скролле) вход вычисляется:
`a=(8-строк)*15 ; ld (SetSpriteJmp+1),a ; jp SpriteJmpBase` — модифицируется ТОЛЬКО
младший байт адреса перехода (страничное выравнивание!). Ноль ветвлений в цикле.

## 3. Page-aligned LUT вместо адресной арифметики
- `addrLUT`: y → адрес строки экрана (`ld h,high addrLUT : ld l,a : ld a,(hl)...`)
- `tilesLUT`: номер тайла → адрес данных
- `mapLUT`: строка карты → адрес в tilemap
Всё чтение таблиц = 4-5 инстр, никаких умножений/сдвигов.

## 4. Render-list вместо немедленного рисования
`putTile` НЕ рисует: кладёт запись (6Б: строк, старт-строка, куда, что) в spritesList;
`drawSprites` рисует ВЕСЬ список одним проходом под DI со стек-хаком (сохранив SP).
= наш dirty-компоновщик, но записи уже содержат готовые адреса (не пересчитывают).

## 5. ISR (ints.a80): палитра + клавиатура + музыка
- Палитра пишется в цветогенератор с МНОГОКРАТНЫМ `out (0Ch)` на каждый индекс
  (6-8 раз) — «в некоторых Векторах очень плохая запись в ОЗУ цветогенератора»
  — ЗНАНИЕ РЕАЛЬНОГО ЖЕЛЕЗА, мотать на ус для наших портов на живой машине!
- Палитра обновляется по флагу (palUpdateFlag) — не каждый кадр.
- Опрос клавиатуры прямо в ISR: `out (03),ряд ; in a,(02)` → ячейки KeyKodN.

## 6. Пайплайн данных
- Графика: PNG → конвертер (res/!parse.bat, vektorizer) → .tiles (interleaved) → ZX0.
- Карты: Tiled TMX → tmxParser → .mapa → ZX0.
- Сжатие: **ZX0** (salvador-компрессор) + **8080-депакер Городецкого (DeZX)** —
  готовая пара для ЛЮБОГО нашего проекта: github.com/ivagorRetrocomp/DeZX.
- Музыка: vt2 (Vortex Tracker) → ВИ53 конвертером vt2vi53 Грачёва — готовое решение
  для звука в наших портах!
- Ассемблер: sjasmplus (z00m128) — dup/edup, метки-выражения ($+1 self-mod cells).

## 7. Применение к нашим проектам
| Техника | Куда | Эффект |
|---|---|---|
| POP-блиттер (данные interleaved в тени) | kvalley блит тайла | 68→~25 инстр (наша 1 плоскость: pop de = 2 СТРОКИ за раз) |
| Page-aligned LUT y→адрес | блиттер/спрайты | −5-8 инстр на вызов |
| Unrolled+computed entry | спрайт XOR-циклы | −20-30% |
| Render-list с готовыми адресами | компоновщик | подготовка при пометке, не при блите |
| Multiple-out палитра | vec_setpal | надёжность на реальном железе |
| ZX0+DeZX | дистрибуция всех ROM | ~50% размера |
| vt2vi53 | звук KV/Knightmare | готовый ВИ53-плеер |
СТРАТЕГИЧЕСКИ: OldTower = нативный движок (16 цветов, 50 Гц) — эталон «переписать
движок» для KV, если решим уходить от рекомпиляции: карта в tilemap+render-list,
логика KV поверх, графика конвертером из MSX-ресурсов.

## 8. Rockman16 (caglrc.cc/ware/896) — разбор бинаря: ЭКСТРЕМУМ скорости
Дизасм /tmp/rockman16.rom (вход 0x450, ISR 0x0D66, RST0→reset, RST8→0x0BAA):
1. **SP = графический курсор всего рендера**: `lxi h,0xDF00 / dad sp / sphl` —
   SP прыгает по колонкам/плоскостям арифметикой (+0xDF00 = переход плоскость+колонка),
   рисование = потоки PUSH.
2. **Графические данные = ИСПОЛНЯЕМЫЙ КОД с внедрёнными RST8**: спрайты/тайлы хранятся
   как код (push-серии); БАЙТ 0xCF (RST 8) ВНУТРИ ПОТОКА = «сменить колонку/плоскость»:
   RST8-обработчик (0x0BAA) правит SP, патчит поток (`mvi a,0xCF / stax d` — временно
   вписывает следующий стоп!, `mvi a,0x39/stax d` — восстанавливает DAD SP) и возвращается
   PCHL. Это компайлед-спрайты в предельной форме: данные сами себя исполняют, разметка
   потока — инструкциями-ловушками. Скорость = теоретический максимум 8080.
3. **Self-modifying ВЕЗДЕ**: операнды lhld/adi/sta патчатся на лету (ячейки = $+1).
4. Музыка ВИ53 (out 0x08-0x0B) стримится прямо в кадровом цикле (ноты из 0x0300+).
5. Тоггл через `xri 1 / sta self / out 0x00` — переключение состояния порта режимов.
ВЫВОД: Rockman16 радикальнее OldTower: не «код рисует данные», а «данные И ЕСТЬ код».
Для нативных портов это верхняя планка; для софт-VDP неприменимо напрямую (наши данные
приходят из MSX-игры в рантайме), но идея RST-хуков в потоке уже частично у нас
(RST8-вход Городецкого) и может разметить будущий рекомпилированный вывод.

## 9. psgVector (Денис Грачёв) — звуковой стек для ванильного Вектора
github.com/DenisGrachev/psgVector (клон /tmp/psgvector). Плеер PSG-файлов
(сырые дампы регистров AY, 50 Гц — экспортируют ЛЮБЫЕ трекеры и эмуляторы),
упакованных psg_compressor Романа Василенко (github.com/vasilenkoroman/psg_compressor).
ГЛАВНОЕ ДЛЯ НАС:
1. **music/playerVI-8080.asm — конвертер AY→ВИ53 НА ЧИСТОМ i8080** (744 строки,
   мнемоники lda/mvi/out!): эмулирует регистры AY в RAM (AYREGS: тоны/микшер/
   громкости), из них раз в кадр строит программирование ВИ53 (порты 0x08-0x0B)
   с трекингом вкл/выкл каналов (vCH1-3, глушение mvi a,$36/out 08).
   = ГОТОВОЕ РЕШЕНИЕ аутентичного звука для нашего KV-порта: наш WRTPSG-стаб
   сейчас пишет в AY (0x14/0x15) — на ванильном Векторе БЕЗ AY-моды будет тишина;
   перенаправить стаб в AYREGS + звать flushVI из vec_isr → звук через штатный ВИ53.
2. Варианты AY-плеера Normal/Extreme/Buffer (буферная предраспаковка → лёгкий
   mus_play в прерывании) + тайминг-замеры бордюром (out (2) вокруг mus_play).
3. music/legend/ = 13 ИТЕРАЦИЙ разработки плеера (player_00..12 + AY-варианты) —
   редкий учебный материал эволюции оптимизации.
4. Макрос mEXX (legend/) — Грачёв решает exx-на-8080 так же, как наш рекомпилятор:
   RAM-ячейки rDE1/rBC1/rHL1 + стек (push/xthl/pop) — независимое подтверждение
   нашей схемы теневых регистров.
ПАЙПЛАЙН для новых проектов: трекер → .psg → psg_compressor → .tbk → плеер
(AY и/или ВИ53). Проще vt2vi53 (не привязан к формату Vortex).
