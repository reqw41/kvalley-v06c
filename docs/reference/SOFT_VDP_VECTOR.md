# Софт-VDP для ванильного Вектора-06Ц — справочник для будущих портов

Извлечено из порта King's Valley (2026-07-02). Канонический код: `tools/kv_z80_to_8080.py`
(`_apply_vector_glue` + `_VECTOR_RUNTIME`); срез сгенерированного рантайма для чтения/переноса:
`tools/vdp/soft_vdp_runtime.asm`. Грабли и хронология: `docs/JOURNAL.md`.

---

## 1. Архитектура нашего софт-VDP

Эмулирует MSX VDP (SCREEN2 + аппаратные спрайты) на уровне **записи байта VRAM** —
оригинальный код игры не меняется, все его `out`-записи в VDP роутятся в `vec_vram_write`.

**Дисплей**: фон → план 0 (2 цвета), спрайты → план 1 (XOR), планы 2/3 скрыты зеркальной
палитрой (индекс дисплея = pl0<<3|pl1<<2|pl2<<1|pl3, палитра инвариантна к битам 1,0)
и используются как 16К теневой RAM.

**Рутины** (см. soft_vdp_runtime.asm):
| Рутина | Назначение |
|---|---|
| `vec_init` | SP из буфера, очистка FB, RST7-вектор, SAT-стоп, палитра |
| `vec_isr` | RST7: depth-cap 3; depth1 = H_TIMI+спрайты, depth≥2 = только звук |
| `SETWR/SETRD/WRTVRM` | установка `vec_vdp_ptr` (WRTVRM сохраняет все регистры!) |
| `vec_vram_write` | ядро: маска `and 3Fh`, роутинг цвет/спрайты/паттерны/имена/SAT |
| `vw_name` | дедуп по name-тени, счётчики tilecnt, блит тайла |
| `vw_wcol/vw_colw` | тень паттерна/цвета + re-blit скан затронутых клеток (гейт tilecnt) |
| `vec_blit_tile` | 68 инстр/тайл: банк=row>>3, режим тайла (кэш) → 5 вариантов цикла |
| `vec_calc_mode` | режим из 8 строк цвета: blank/pat/~pat/solid/mixed |
| `vec_render_sprites` | эмуляция спрайт-юнита: XOR-стирание прошлого SAT + XOR-рисование |
| `RDVRM` | чтение любой тени, СОХРАНЯЕТ HL/DE (FlipPatrones-цикл!) |
| fast-paths | setFillVRAM ≥16К → memset теней; DEtoVRAM → memcpy в тень |

**Три правила, купленные кровью** (3 инцидента за сессию):
1. Вставленный код обязан 1-в-1 повторять **регистровый контракт** заменяемой рутины
   (HL в DEtoVRAM, A в setFillVRAM-гейте, HL/DE в RDVRM).
2. VDP-указатель — **глобальное состояние**, как железо: не сохранять/восстанавливать в ISR.
3. VDP-адрес несёт биты режима (0x4000) — маскировать во всех путях.

## 2. Бюджет карты памяти (текущая раскладка KV)

| Диапазон | Размер | Что |
|---|---|---|
| 0000-00FF | 256 | вектор-страница (RST7 @0038) |
| 0100-~60xx | ~24.5К | код игры + рантайм VDP (~2.5К) — **margin к MAP проверять после каждой сборки!** |
| 6200-~7850 | ~5.7К | MAP: переменные игры (0x8A0) + ячейки VDP + name-тень (768) + scratch |
| ~7850-7FFF | ~2К | свободно |
| 8000-9FFF | 8К | план 0 — ФОН (видим) |
| A000-BFFF | 8К | план 1 — СПРАЙТЫ XOR (видим) |
| C000-C07F | 128 | SAT-тень |
| C080-C87F | 2К | спрайт-паттерны |
| C880-C8FF | 128 | SAT-drawn (для XOR-стирания) |
| C900-E0FF | 6К | паттерны, 3 банка |
| E100-E3FF | 768 | tilecnt (счётчик присутствия тайла на экране) |
| E400-FBFF | 6К | цвет, 3 банка |
| FC00-FEFF | 768 | tilemode (кэш режимов) |
| FF00-FFFF | 256 | свободно |

Итого теней: 15.7К из 16К скрытых планов — почти впритык. Для игр без цвет-таблицы
(или identity-теней, см. §4) освобождается 6-12К.

## 3. Бюджет кадра

Вектор-06Ц: CPU 3 МГц, кадр 50 Гц, 312 линий × 192 такта = **59904 такта/кадр**
≈ **6600 инструкций** (средняя i8080 ~9 тактов).

Стоимость наших операций (инструкций ≈ тактов/9):

| Операция | Инстр | Тактов | Штук в кадр (100% CPU) |
|---|---|---|---|
| `vec_vram_write` (байт, без блита) | ~45 | ~400 | ~150 байт |
| блит тайла (дедуп-промах) | ~110 | ~1000 | ~60 тайлов |
| дедуп-хит (тайл не изменился) | ~50 | ~450 | ~130 |
| re-blit скан банка (256 клеток) | ~2100 | ~19К | 3 (треть кадра!) |
| спрайт 16×16 XOR (2 колонки) | ~600 | ~5.4К | ~11 |
| полный кадр спрайтов (стирание+рисование 4 спрайта) | ~5К | ~45К | 0.75 кадра! |
| bulk memset 16К (fast-path) | ~300К | — | ~5 кадров однократно |

Вывод: **геймплей упирается в спрайты** (стирание+рисование каждый кадр),
**загрузка — в per-byte поток**. Полная перерисовка экрана (768 тайлов ≈ 84К инстр)
= ~13 кадров ≈ 0.26 с.

Сравнение со средой: MSX `out (98h),a` = 12 тактов/байт; Городецкий ≈ 30-60 тактов/байт
(Z80+RST8+identity); мы ≈ 400-700 тактов/байт (i8080 + макро-раздувание + фичи).

## 4. Анализ порта Городецкого (kvalley_postinit64k.bin, дизасм 0x12e4+)

**Главное открытие: у него ТА ЖЕ архитектура софт-VDP** — перехват записи байта VRAM,
а не «нативный порт рендера». Но каждый слой тоньше:

| Приём | Код | Эффект |
|---|---|---|
| **RST 8 как вход записи** | `0008: jp 12e4`; сайты `out` пропатчены в `rst 8` (1 байт!) | диспетчер за 11 тактов, патч минимален |
| **Identity-тени** | тень VRAM 0x0000-0x3FFF лежит ПО ТЕМ ЖЕ адресам RAM | ноль трансляции адреса: `and 3Fh; ld h,a; ld (hl),a` |
| **Роутинг** (0x12e4) | `and 3Fh` → цвет<0x18 ИГНОР; спрайты→0x1157; name 0x38/39/3A → 3 блиттера; паттерны → `ld (hl),a` | как у нас, минус цвет/режимы/счётчики |
| **Тайл-блиттер** (0x1171) | дедуп `cp (hl)`; **развёрнутые 8 строк** `ld a,(hl)/ld (de),a/inc hl/dec e` ×8 без цикла | ~230 тактов/тайл (у нас ~1000) |
| **Банк → плоскость** | name-страница 0x38→план 0xC0xx, другие — свои планы | «цвет по третям экрана» бесплатно, вместо честной цвет-таблицы |
| **Стек-блит** | `ld sp,src / pop de / ld (hl),e / inc hl / ld (hl),d …` развёрнуто (0x0f8c) | чтение 2 байт за 11 тактов — самый быстрый копир 8080/Z80 |
| **Сжатие** | ROM упакован, деэкомайзер = «8080-recompiled deexomizer by Ivan Gorodetsky» | см. §5 |

Что он выбросил (наши «лишние» фичи): честная цвет-таблица (режимы тайлов),
re-blit при смене паттерна (мигание сокровищ у него, вероятно, через name-перезапись),
счётчики присутствия, эмуляция RDVRM-зеркалирования (пропатчил соответствующие места?).

## 5. incursiondelrio (svofski) + Exomizer — сжатие и вывод

- **Exomizer 2.0** (Magnus Lind; форк bitshifters): LZ-пакер, декомпрессор ~150-200 байт.
  У svofski: `incursion.rom` (raw) + `incurzion.rom` (сжатый); декомпрессор —
  **8080-рекомпилированный deexomizer Городецкого** (готовый, брать его!).
  Распаковка один раз при загрузке → в RAM → старт. Даёт ~40-60% размера ROM.
  Для нас: наш ROM ~24К+ данных → упаковка в ~12-14К = быстрее грузится с ленты/диска.
- **Вывод кадра**: single-frame (без двойного буфера), все спрайты перерисовываются
  каждый кадр (нет накопления дрейфа), «шторки» (wipes.inc) в размер врага маскируют
  края при вертикальном скролле `out 3`, preroll вместо предзаполнения.
- **Пайплайн**: makesprites.py генерит развёрнутый код спрайтов из PNG (компайлед-спрайты:
  спрайт = код, а не данные — быстрейший вывод ценой ROM, отлично сочетается с exomizer).

## 6. ПРЕДЛОЖЕНИЕ: эффективный метод вывода кадра (v2 драйвера)

Синтез нашего (универсальность) + Городецкого (стоимость) + svofski (кадровая дисциплина):

**A. Записи дешёвые, рисование кадровое — «dirty-tile компоновщик»:**
1. `vec_vram_write` больше НЕ рисует: только тень + пометка dirty-бита клетки
   (name-запись → dirty[cell]; паттерн/цвет → через tilecnt-гейт пометить dirty клетки
   тайла, БЕЗ немедленного блита). Стоимость записи падает до ~15-20 инстр.
2. Раз в кадр (vec_isr, depth 1, после H_TIMI): скан dirty-битмапа (768 бит = 96 байт,
   `or a`-скан по 8 клеток за раз) → блит только грязных, **с бюджетом** (≤48 тайлов/кадр
   ≈ 5К инстр; остаток доедается в следующих кадрах — плавная деградация вместо фриза).
3. Спрайты XOR после блитов (как сейчас).
   Выигрыш: игра, пишущая одну клетку N раз за кадр, платит за 1 блит; пики загрузки
   размазываются; per-byte путь дешевеет в ~3 раза.

**B. Удешевить сам блит (по Городецкому):**
- Развернуть 8 строк без счётчика (68 → ~40 инстр для режима «pat»),
- identity-тени, где возможно (если раскладка RAM игры позволяет — у KV занято кодом,
  но для игр ≤32К кода это ноль трансляции адреса),
- RST-вход вместо `call vec_vram_write` (если RST-слоты свободны): −2 байта и −6 тактов на сайт.

**C. Bulk — стек-блит:** memset/memcpy теней и очистки планов через
`ld sp,dst / push rr` (запись 2 байт = 11 тактов) — ×3 к нашим `ld (hl),a/inc hl` циклам.
Осторожно: DI на время (SP занят), вернуть SP, учесть ISR.

**D. Дистрибуция:** exomizer 2.0 + готовый 8080-deexomizer Городецкого; компайлед-спрайты
для своих игр (не рекомпиляций).

Ожидаемый эффект для KV: загрузка экрана 0.26с → ~0.1с, геймплейный кадр — спрайты
остаются главной статьёй (~45К тактов на 4 спрайта), лечится компайлед-спрайтами
или сокращением перерисовки (стирать/рисовать только сдвинувшиеся).

## 7. Развязка физики и графики по кадрам + анти-моргание (план v2.1)

Принцип: **логику игры не трогаем** (fidelity рекомпиляции), развязка только на стороне драйвера.

1. **Физика ↔ графика**: тик игры пишет тени+dirty (~15 инстр/запись) — «логический кадр»;
   компоновщик рисует с бюджетом ≤N тайлов — «графический кадр». Гейт tickInProgress игры
   уже даёт деградацию логики к 25 Гц под нагрузкой; компоновщик делает её детерминированной.
2. **Спрайт-планировщик** (рендер, не логика!): герой — каждый кадр; враги — половинами
   через кадр (позиции всегда свежие из SAT-тени; визуально 25 Гц при 1-2px/кадр незаметно).
   Бюджет спрайтов ~45К → ~22К тактов/кадр.
3. **Анти-моргание — геометрия луча**:
   (а) пары erase+draw НА СПРАЙТ (не erase-all→draw-all): окно уязвимости 45К → ~5К тактов;
   (б) весь спрайт-рендер сразу по vblank-IRQ, пока луч в верхней рамке: до входа луча в
   игровое поле ~29К тактов; герой+2 врага ≈ 16К — влезают ЦЕЛИКОМ → моргание исключено
   геометрически (метод svofski/incursiondelrio: «все спрайты сразу по прерыванию»).
   NB: наш vec_isr уже на RST7=vblank; порядок внутри: спрайты ДО H_TIMI (луч выше),
   компоновщик тайлов ПОСЛЕ (тайлы фона статичны — моргание не про них).
4. НЕ делать: гейтить AI (AI_Momias) через тик — реально замедляет врагов, ломает
   байт-точность поведения. Разносить только рендер.
