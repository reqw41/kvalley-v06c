# KV engine v2 — план-разделённый рендер 2+2 (порт метода Monty) → flicker-free

**Дата:** 2026-07-08
**Статус:** ЧЕРНОВИК на утверждение.
**Причина:** весь M3 (tile-reblit/saved-pixels/POP/растровый порядок/K-тюнинг/планировщик) —
это обход флика, вызванного тем, что v2 засунул спрайты в планы ФОНА (0,1) и стирает
фон под ними. Соседний проект Monty (~/projects/monty-recomp) решил это архитектурно:
**спрайты в отдельные планы 2,3, фон в 0,1 — фон при движении спрайта НЕ трогается → нет
зазора → нет флика.** Плюс палитра программируется один раз (нет палитра-флика). Готовый
код: `src/vdp_shim.asm` (blit2/clear_box/program_palette).

## Цель

Переписать рендер v2 на **схему 2+2** (4 плана Вектора, 32КБ видео):
- **flicker-free архитектурно** (фон нетронут спрайтами) — убирает нужду в гонке
  луча/планировщике/K-тюнинге,
- **быстрее** (спрайт = чистая перезапись в свои планы, не масочный RMW),
- **16 цветов** (4 фона + 3-4 спрайта против нынешних 4).

## Архитектура

### Планы (32КБ фреймбуфер 0x8000-0xFFFF)
| План | Адрес | Назначение |
|---|---|---|
| 0 | 0x8000 | фон бит0 |
| 1 | 0xA000 | фон бит1 |
| 2 | 0xC000 | спрайт бит0 |
| 3 | 0xE000 | спрайт бит1 |
Шаг плана = +$20 в СТАРШЕМ байте адреса. `planeH = $80+col` (фон), `$C0+col` (спрайты).

### Палитра (16 слотов, порт $02=индекс, $0C=цвет ×8)
Программируется ОДИН раз при загрузке уровня (защёлкивается по кадру, persist — НЕ каждый
кадр). Схема: где спрайт-планы (2,3)=00 → цвет фона f(pl0,pl1) [4 цвета]; где ≠00 → цвет
спрайта f(pl2,pl3) [3 цвета], перекрывает фон. Формат байта Вектора: `(b<<6)|(g3<<3)|r3`.

### Фон → планы 0,1
Тайлы блитятся в планы 0,1 (2 плана = 4 цвета). Рисуется при загрузке уровня + при
изменении (копание/гемы) через dirty. **Спрайты фон НЕ трогают** → dirty-фон и спрайт-рендер
независимы (уходит связка bg-dirty→sprite-fallback, из-за которой мигали гемы).

### Спрайты → планы 2,3 (порт blit2/clear_box Monty)
Покадрово: `clear_box` старых позиций (планы 2,3) → `blit2` текущих (планы 2,3). Фон нетронут.
- `blit2`: перезапись 3 байт/строку (16px+сдвиг) × 16 строк × 2 плана, прозрачн.=0. БЕЗ RMW.
- `clear_box`: обнуление того же региона.
- Порядок: меньший номер спрайта ПОВЕРХ (приоритет MSX); герой=2 наложенных слоя (одна позиция).

### Спрайт-паттерны в формате 2+2
Спрайт 16×16 = **64 байта** (план2: 16 строк×2 + план3: 16 строк×2). Конвертер из текущих
scn_sprpat (MSX-раскладка) + цвет-LUT (MSX-цвет спрайта → 2-битное значение план2/3).
`sprcol_lut[16]`.

## Карта памяти (бюджет)
- 0x0100-0x3FFF (~16КБ): код (движок+рендер).
- 0x4000-0x7FFF (~16КБ): данные — tilemap, bgpat (2 плана!), sprpat (2+2, 64Б/спрайт),
  сцена/состояние. **Проверять margin — bgpat/sprpat в 2 плана крупнее.**
- 0x8000-0xFFFF (32КБ): 4 плана фреймбуфера.
Итого код+данные ≤ 32КБ (0x0100-0x7FFF). Сейчас ~26КБ — влезаем, но контролировать.

## Что выбрасывается из M3 (обход, больше не нужен)
- tile-reblit erase, saved-pixels, POP-copy эрейз — фон под спрайтом больше не стирается.
- Растровый порядок / гонка луча — флика нет по построению.
- Планировщик (K-cap/defer/round-robin) — не нужен (спрайты дёшевы, влезают).
- only-moved для спрайтов — опционально (clear+blit всех дёшев; можно оставить для скорости).
- set_palette каждый кадр — палитра программируется раз.
Что ОСТАЁТСЯ: bg dirty-tile путь (планы 0,1) для копания/гемов; build_sprites (готовит список).

## Пошаговая миграция (без регрессии; валидация на каждом шаге)
Эталон меняется (2+2 вывод ≠ прежний 2-плановый), поэтому вводим НОВЫЙ эталон: рендер
против ожидаемой 2+2-композиции (фон-план 0,1 из тайлов + спрайт-план 2,3 из blit2),
проверяемой headless (планы читаются из памяти) + визуально в браузере.

1. **Палитра 2+2 + очистка 4 планов** (program_palette, clear). Пустой цветной экран.
2. **Фон в планы 0,1** (2-плановый тайл-блит + bgmap-LUT цвета). Лабиринт в цвете, без спрайтов.
3. **Спрайт-паттерны → 2+2** (конвертер + sprcol_lut). Данные готовы.
4. **blit2/clear_box порт** (планы 2,3). Один статичный спрайт поверх фона.
5. **Спрайт-цикл** (clear старых → blit текущих). Герой+мумии двигаются БЕЗ флика.
6. **Гемы**: искра-спрайт (планы 2,3) мигает над гемом — как спрайт, не тайл-ореол.
7. **Интеграция логики** (hero_tick/ai_momias → build_sprites → рендер). Играбельно, flicker-free.
8. **ГЕЙТ:** браузер — герой/мумии/сияние стабильны при движении; 16 цветов; тик влезает.

## Тестирование
- Headless: планы 0,1 (фон) и 2,3 (спрайты) читаются из памяти — проверка композиции.
- Визуально: браузер vector06js — нет флика при движении 2+ объектов.
- i8080-чистота (check_i8080).
- Бюджет: код+данные < 32КБ; тик < 59904.

## Открытые вопросы
- Точный порядок бит планов в индексе палитры Вектора (свериться с Monty hw.inc / эмпирически).
- Цвета: реальная палитра KV (сколько фон/спрайт) — влезаем ли в 4+3 (2+2) или нужен другой сплит.
- Конверсия sprpat: MSX-квадранты (TL,BL,TR,BR) + цвет→2бит; сверить с blit2 порядком чтения.
- Гем/алмаз: спрайт или фон-тайл (нашли искру-спрайт; алмаз-центр — уточнить).
- Переиспользовать код Monty напрямую (blit2/clear_box/program_palette) — адаптировать адреса/данные.
