# King's Valley engine v2 — M2a: нативный сборщик сцены + dirty-фон (дизайн)

**Дата:** 2026-07-03
**Статус:** утверждён к реализации
**Родитель:** docs/superpowers/specs/2026-07-03-kvalley-engine-v2-design.md (движок v2, C-native)
**Предшественник:** M1 (render-драйвер) — ЗАВЕРШЁН, отревьюен SOUND.

## Цель

Первый нативный игровой модуль: код на i8080, который **строит сцену** (tilemap +
sprite-list) для комнаты King's Valley, воспроизводя вывод v1 (`drawRoom` +
`updateSprites` + `AI_Cuchillos`), и **dirty-фон** (render_frame рисует только
изменённые клетки — ключ к 50 Гц). Доказывается пиксель-в-пиксель и по сцене
против v1 (эталон), сначала кормится состоянием живого v1 (как в M1).

## Обоснование

Профиль M2-kickoff: геймплейный тик v1 = 64.6% MSX-VDP-эмуляция (устраняется швом
сцены) + 34.1% логика. M2a закладывает нативный путь «данные уровня → сцена →
dirty-render», убирая перехват WRTVRM и полный блит каждого кадра. Это фундамент
динамики (M2b физика кладёт актёров в ту же сцену).

## Механика v1 (что воспроизводим)

- `setupStage` распаковывает лабиринт пирамиды в **MapaRAM** (map-ID: семантика
  тайла — кирпич/лестница/пусто/дыра/…). ВНЕ объёма M2a (нативная распаковка — позже).
- `setupRoom`: берёт из MapaRAM экран текущей комнаты (ProtaRoom, 32 клетки шириной),
  зовёт `drawRoom` (map-ID → tile-ID через `getTileFromID`, пишет в name-таблицу
  0x3800), `updateSprites` (актёры прота→SAT), `AI_Cuchillos` (ножи→SAT).
- Ключевое отличие map-ID vs tile-ID: MapaRAM хранит СЕМАНТИКУ (что за объект),
  name-таблица — ПАТТЕРН (какой тайл рисовать). `getTileFromID`/`drawRoom` — маппинг.

## Архитектура M2a

Новый нативный модуль `v2/scene_builder.asm` (машинно-независимый, Слой 1) +
расширение драйвера `v2/driver_vector.asm` dirty-путём.

```
MapaRAM (map-ID, из v1) ──scene_builder: build_tilemap (map-ID→tile-ID)──► set_tile → scn_tilemap
актёр-структуры (из v1) ──scene_builder: build_sprites──────────────────► scn_sprites/scn_nsprites
                          set_tile(cell,id): tilemap[cell]=id + пометка dirty
render_frame ──► блит ТОЛЬКО dirty-клеток фона (+ спрайты как в M1) ──► планы
```

### Компоненты и интерфейсы

- `set_tile(cell, id)` (в scene.inc/driver): `scn_tilemap[cell]=id`; если id изменился —
  добавить cell в `scn_dirty` (список 2Б/клетка LE), инкремент `scn_ndirty`.
  ЕДИНСТВЕННОЕ место правки фона (шов остаётся чистым).
- `build_tilemap` (scene_builder): вход = указатель на MapaRAM-экран комнаты;
  для 24×32 клеток: map-ID → tile-ID (порт логики v1 `drawRoom`+`getTileFromID`),
  вызвать `set_tile`. Гейт: `scn_tilemap` == v1 name-таблица (0x3800 тень 0xE100).
- `build_sprites` (scene_builder): вход = актёр-структуры (прота, мумии, ножи,
  предметы); заполнить `scn_sprites` (Y,X,FRAME,COLOR,FLAGS) + `scn_nsprites`,
  воспроизводя `updateSprites`+`AI_Cuchillos`→SAT. Гейт: `scn_sprites` == v1 SAT (0xC880).
- `render_frame` (расширение M1): рисовать фон ТОЛЬКО по `scn_dirty` (не все 768);
  на загрузке все клетки dirty → полный блит раз, дальше только изменения. Спрайты
  как в M1. Гейт: пиксель-компар планов == v1; после единичного `set_tile` —
  переблитывается только та клетка (не весь экран).

## Пошаговая миграция (без регрессии, v1 = эталон)

Инструменты готовы: экстрактор/пиксель-компар/локстеп (tools/verify/), check_i8080.js.

- Расширить экстрактор: захватывать ВХОД (MapaRAM-экран + актёр-структуры v1) вместе с
  РЕФЕРЕНСОМ (name-таблица + SAT + планы), уже частично есть.
- `build_tilemap` нативно → гейт tilemap==name-таблица на PYRAMID-01 + ещё 2 комнатах.
- `build_sprites` нативно → гейт sprites==SAT.
- Dirty-фон в render_frame → гейт: полный кадр == v1 (пиксель); единичный set_tile →
  минимальный переблит (счётчик перебличенных клеток == 1).
- i8080-гейт (check_i8080.js) на весь модуль.

Каждый шаг: запускаем, доказываем против v1 бит-в-бит, коммитим.

## Вне объёма M2a (следующие суб-майлстоны)

- Нативная распаковка уровня `setupStage` (M2a.2 или отдельно) — пока MapaRAM из v1.
- Физика/управление героя (M2b), AI мумий (M2c), ножи/ловушки/game-flow (M2d).
- Сжатие данных ZX0 (M4).

## Тестирование

- Локстеп сцены: v2 `build_tilemap`/`build_sprites` вывод == v1 name-таблица+SAT (≥3 комнаты).
- Пиксель-компар: планы v2 == v1 после dirty-render.
- Dirty-корректность: единичный set_tile → ровно 1 клетка перебличена, экран == v1.
- i8080-чистота: check_i8080.js OK.
- Все прогоны headless (tools/verify/), сверка с браузером по необходимости.

## Открытые вопросы для плана

- Точный map-ID→tile-ID маппинг: порт v1 `drawRoom`/`getTileFromID` (адреса в /tmp/kvv.sym).
- Формат актёр-структур (ProtaY/X, momiaData, knifesData) — адреса из .sym, читаем как v1.
- Dirty-список vs битмап — список (единицы клеток/кадр в геймплее); на загрузке
  спец-путь «все dirty» (флаг full-render) чтобы не забивать список 768 клетками.
