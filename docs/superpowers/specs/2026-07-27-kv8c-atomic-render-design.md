# KV 8C: Атомарный кадр и буферный рендер (дизайн)

**Дата:** 2026-07-27. **Автор идеи:** Борис («графику готовить в буфер, логику считать
отдельным сплошным игровым циклом, чтобы не ломалась последовательность, а музыку и быструю
отрисовку делать по прерываниям — тогда утилизируется простой кадра»).

## 1. Проблема (факты, всё замерено)

Текущая схема: `RST7 (строка 0) → vec_isr` → на глубине 1: палитра → brillo → клавиатура →
звук → **`call H_TIMI → tickMain`** — весь игровой тик живёт ВНУТРИ прерывания. Рендер
спрайтов (`vec_nat_sprites`: Pass-R restore → save+draw по флагам) вызывается из
`updateSprites` — то есть из СЕРЕДИНЫ тика, в непредсказуемой точке кадра.

Следствия (каждое подтверждено трапами/замерами 2026-07-27):

- **Разрыв кадра.** Трап на исчезновении створки ворот: в кадре N исполнились только
  restore слотов 5..0, save+draw — в кадре N+1. Между ними экран показан БЕЗ спрайтов
  (мигание, которое видит Борис), а слоты save-under рассогласованы → остаток 8/16 байт
  створки в p1/p2 навсегда (над чёрным фоном = idx4 = мигает вместе с аурой).
- **Простой кадра не утилизируется:** dummyLoop 27–41% в покое, при этом пики 100%.
- **Гонка с лучом** (фликер верхних строк) — рендер стартует когда угодно.
- Смена цветов героя в воротах — тот же класс (перекраска через ISR-палитру и рендер
  разъезжаются по кадрам).

Бюджеты (константы дизайна):
- Кадр 59904 тактов, растр 312 строк (22 vsync + 18 бордюр + 256 экрана + 16 бордюр),
  ≈192 такта/строка.
- Полный проход рендера спрайтов сейчас ≈17–20К тактов (save/restore ≈9К после развёртки,
  rot-блиты ≈5К, фазы ≈3К) при 4–6 видимых спрайтах.
- Безопасное окно от RST7 до прихода луча к первой строке спрайтов:
  (22+18) строк гашения+бордюра + HUD (~16 строк) ≈ **56 строк ≈ 10.7К тактов** — проход
  НЕ влезает.
- **С лого-зоной 64 строки сверху** (задача «лого в игре»: статичная зона в начале
  развёртки): 40+64+16 ≈ **120 строк ≈ 23К тактов** — полный проход ВЛЕЗАЕТ с запасом.
  Лого-зона — не украшение, а функциональная часть этого дизайна.

## 2. Целевая архитектура

```
ГЛАВНЫЙ ЦИКЛ (бывший dummyLoop)            ISR (RST7, каждый кадр, фиксированная цена)
──────────────────────────────             ─────────────────────────────────────────
loop:                                      депь 1:
  ждать флаг vblank_go                       музыка (updateSound + vec_flushvi)
  vblank_go := 0                             палитра (vec_pal_apply, vec_brillo_pal)
  call tickMain      ; сплошной тик,         клавиатура (vec_scan_keys)
                     ; последовательность    РЕНДЕР: если snap_ready:
                     ; не рвётся                 снапшот → рабочая копия
  снапшот sprAttrib (42Б) + snap_ready:=1        полный проход restore→save→draw
  jp loop                                        (атомарно, в окне до прихода луча)
                                             vblank_go := 1
                                           депь ≥2 (тик перелез кадр): только музыка
```

Ключевые инварианты:
1. **Атомарность прохода:** restore и draw одного прохода — всегда в одном кадре, в начале
   развёртки. Экран физически не может быть показан «наполовину снятым».
2. **Консистентность данных:** рендер читает только снапшот, снятый на границе тика.
   Тик никогда не наблюдается рендером в середине обновления sprAttrib.
3. **Темп игры сохраняется:** тик стартует по кадровому флагу (1 тик/кадр); длинный тик
   пропускает кадры так же, как сейчас (frame-drop coupling не меняется — тайминг мумий
   через `timer` остаётся прежним).
4. Фоновые блиты тика (копка/гемы/двери → `vec_blit_tile`) продолжают идти напрямую из
   тика (как сейчас): они не образуют пар «снять/нарисовать» и мигания не дают. Их
   fixup-хук в save-слоты сохраняется.

## 3. Инкременты (каждый с гейтом, каждый деплоится отдельно)

**I0 — детектор (инструмент, без правок кода игры).**
`tools/verify/atomic_gate.js`: трапы vec_su_restore/save/vec_nsx; PASS = за 20000 кадров
ни один проход не пересёк границу кадра и нет кадров «спрайты сняты, не нарисованы».
На ТЕКУЩЕМ билде обязан FAIL'ить (воспроизводит баг) — это baseline.

**I1 — рендер в начало ISR (минимальный фикс мигания, тик остаётся в ISR).**
Вынести вызов рендера из updateSprites в vec_isr глубины 1 ДО `call H_TIMI`; updateSprites
в тике становится no-op. На границе кадра тик не исполняется → sprAttrib консистентен без
снапшота. Порядок отрисовки — сверху вниз по Y (за лучом). Разрыв кадра исчезает; остаточная
гонка с лучом (проход 17-20К > окно 10.7К) остаётся до I3 — это старый, не новый флик.
Риск: +17-20К фиксированной работы в начале каждого ISR — при тике, перелезшем кадр,
рендер теперь исполняется на каждом кадре, а не раз на тик → замерить frame_budget
(ожидание: покой без изменений — рендер и так шёл каждый кадр из тика).
Гейты: atomic_gate PASS, door_hole (остаток створки=0), pickup_audit, hero_vis2, OFF-identity.

**I2 — тик в главный цикл (схема Бориса целиком).**
- dummyLoop → цикл `wait vblank_go → tickMain → снапшот+snap_ready`.
- vec_isr глубины 1: музыка/палитра/ввод/рендер-по-снапшоту + `vblank_go:=1`;
  H_TIMI из ISR больше не зовётся.
- Снапшот: 21×4=84Б копия sprAttrib (ldir-хелпер, ~1К тактов).
- Вложенные прерывания при длинном тике: остаётся ветка «только музыка» (депь≥2 уже есть).
- Локстеп-гейты: z80_logic_gate сравнивает по ТИКАМ — логика тика не меняется, порядок
  «палитра/ввод до тика» сохраняется тем, что тик стартует сразу после ISR. Ожидаемый
  timing-reseed демо — принят ранее (вариант A).
Гейты: I1-гейты + z80_logic_gate (потиково) + длинный прогон 3 attract-цикла + MiSTer.

**I3 — окно луча и лого-зона (де-фликеринг).**
- Лого King's Valley в верхние 64 строки (рендер в потоке из тайлов титула, без второй
  картинки — требование Бориса). Статичная зона удлиняет безопасное окно до ≈23К тактов.
- Рендер-проход целиком в окне → гонка с лучом устранена архитектурно.
- Перегруз (7 мумий + нож): планировщик атомарного переноса объекта на следующий кадр
  (приоритет герой > мумии > прочее; erase+draw объекта строго в одном кадре — правило
  уже сформулировано в проекте).
Гейты: покадровый PNG-стробоскоп зоны спрайтов (нет полукадров), замер худшего кадра.

**I4 (опционально, после замеров) — командный буфер фоновых блитов.**
Если фон-блиты тика начнут заметно рвать луч — копить их в очередь и исполнять в ISR-окне.
Сейчас не требуется (события редкие).

## 4. Что НЕ делаем
- Не переносим музыку из вложенных тиков (работает, не трогаем).
- Не меняем frame-drop coupling / темп игры.
- Не буферизуем пиксели (только атрибуты спрайтов): пиксельный двойной буфер Вектору
  не по карману, да и не нужен.

## 5. Порядок и откаты
I0 → I1 (флаг KV_NO_ISRREND) → замер/браузер/MiSTer → I2 (флаг KV_NO_MAINTICK) → I3
(лого: KV_NO_GAMELOGO; планировщик: KV_NO_SCHED). Каждый инкремент: OFF байт-идентичен,
откат предыдущего шага байт-идентичен, i8080-чистота, полный набор регресс-гейтов сессии
(pickup_audit по цвету гема, door_hole, hero_vis2, белые idx12=3027, frame_budget).
