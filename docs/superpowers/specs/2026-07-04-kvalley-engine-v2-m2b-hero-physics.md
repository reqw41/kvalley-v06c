# King's Valley engine v2 — M2b: нативная физика героя + two-pass спрайты (дизайн)

**Дата:** 2026-07-04
**Статус:** утверждён к реализации
**Родитель:** docs/superpowers/specs/2026-07-03-kvalley-engine-v2-design.md
**Предшественники:** M1 (render-драйвер) ✅, M2a (сборщик сцены + dirty-фон) ✅.

## Цель

Первый нативный модуль ДИНАМИКИ: код на i8080 физики героя King's Valley
(гравитация, ходьба, лестницы, прыжок, копание), читающий абстрактный ввод и
обновляющий состояние прота + сцену, **локстеп-доказанный против v1** потиково.
Плюс **two-pass XOR-спрайты** в драйвере (стереть прошлый кадр → нарисовать
новый), чтобы герой видимо ДВИГАЛСЯ без XOR-мусора. Итог — браузерный ROM, где
герой ходит/копает под нативной физикой, бит-в-бит как v1.

## Обоснование

M2a доказал статичную сборку сцены. M2b добавляет первый источник движения —
героя. Локстеп-верификатор (tools/verify/) и headless-харнесс уже есть.
Two-pass спрайты — проверенный конвейер v1 (erase-all→draw-all, мультиплекс-
безопасно); M1 отложил его (одиночный кадр не требовал). Для анимации он нужен.

## Механика v1 (что воспроизводим)

- Физика героя живёт внутри монолитного `tickGame` (0x10A9). Секция героя:
  чтение ввода → обновление состояния прота по гравитации/ходьбе/лестницам/
  прыжку/копанию → запись spr-атрибутов (setAttribProta, уже в M2a build_sprites).
- Состояние прота (адреса .sym): protaStatus=0x6C34, ProtaY=0x6C37,
  ProtaXdecimal=0x6C38 (дробная X), ProtaX=0x6C39, ProtaRoom=0x6C3A,
  protaFrame=0x6C3F, protaSentido (направление). Точные границы секции и формат
  флагов ввода — вскрыть в плане чтением tickGame.
- Копание: изменяет MapaRAM (кирпич→дыра, map-ID группы 9 tilesAgujero) — в v2
  это `set_tile(cell, tile-ID-дыры)` (dirty-путь M2a уже готов).

## Архитектура M2b

Новый нативный модуль `v2/hero.asm` (Слой 1, ядро) + two-pass в `v2/driver_vector.asm`.

```
input_read → hero_tick (гравитация/ходьба/лестница/прыжок/копание)
   → обновляет prota-состояние (Y/Xdec/X/Frame/Sentido/Status) в ОЗУ сцены-ядра
   → при копании: set_tile(cell, дыра)   [dirty-путь M2a]
   → build_sprites (M2a) кладёт героя в scn_sprites
render_frame: two-pass спрайты (erase прошлый кадр XOR → draw новый XOR) + dirty-фон
```

### Компоненты и интерфейсы

- `input_read()` (Слой 3, драйвер): читает клавиатуру/джойстик Вектора →
  стандартные биты кнопок (вверх/вниз/влево/вправо/копать) в байт. Для локстепа
  харнесс подставляет записанный ввод.
- `hero_tick(input)` (hero.asm, ядро): порт секции героя v1 tickGame. Читает
  prota-состояние + input, применяет физику, пишет новое prota-состояние; при
  копании зовёт set_tile. Машинно-независим. Гейт: prota-состояние v2 == v1
  потиково (локстеп на записанном вводе).
- Two-pass спрайты (driver_vector.asm): драйвер держит копию «спрайтов прошлого
  кадра»; render_frame сперва XOR-стирает их, затем XOR-рисует текущие
  scn_sprites (проверенный конвейер v1, мультиплекс-безопасно). Ядро об этом не
  знает. Гейт: анимация без остаточного мусора; кадр == v1 (пиксель-компар).

## Пошаговая миграция (без регрессии, v1 = эталон)

- Расширить экстрактор/харнесс: захватывать prota-состояние ДО и ПОСЛЕ тика v1 на
  записанном вводе (вход локстепа + эталон).
- `input_read` + формат кнопок → гейт: биты v2 == флаги ввода v1 на записанном вводе.
- `hero_tick` нативно, по под-механике инкрементально (гравитация/падение →
  ходьба → лестницы → прыжок → копание), каждая под-механика локстеп-сверяется с
  v1 на вводе, её упражняющем. Не интегрируется, пока не совпало.
- Two-pass спрайты в драйвере → гейт: многокадровая анимация героя == v1 (пиксель),
  XOR-мусор отсутствует.
- Демо: нативная физика + two-pass рендер → герой ходит/копает в браузере.
- i8080-гейт (check_i8080.js) на весь модуль на каждом шаге.

## Вне объёма M2b (следующие суб-майлстоны)

- AI мумий (M2c), ножи/ловушки/предметы/game-flow (M2d), спрайты двери/прочие.
- Нативная распаковка уровня setupStage (пока MapaRAM из v1).
- Сжатие ZX0 (M4).

## Тестирование

- Локстеп prota-состояния: v2 hero_tick == v1 (protaStatus/Y/Xdec/X/Frame/Sentido)
  потиково на записанных вводах, упражняющих каждую под-механику (ходьба/падение/
  лестница/прыжок/копание) + смена MapaRAM при копании.
- Пиксель-компар: планы v2 == v1 после two-pass рендера на многокадровой анимации.
- i8080-чистота: check_i8080.js OK.
- Демо: браузерный ROM с движущимся героем (headless-прогон записанного ввода +
  ссылка vector06js).

  ходьбы?) — вскрыть чтением исходника.
- Формат флагов ввода v1 (какие биты, порядок опроса клавиш/джойстика).
- Полный формат prota-состояния для локстепа (все байты, влияющие на физику:
  скорость/фаза прыжка/таймеры копания — не только Y/X/Frame).
- Хранилище «прошлого кадра спрайтов» для two-pass (где в ОЗУ драйвера).
