# Дизайн: полное выпиливание soft-VDP из King's Valley (Вектор-06Ц)

Дата: 2026-07-22. Ветка проекта: порт King's Valley (Konami MSX Z80) на Вектор-06Ц (i8080)
через сорс-рекомпиляцию (`tools/kv_z80_to_8080.py`).

## Цель

Убрать **все** остатки программного VDP-слоя (soft-VDP): нативный блит прямо во
фреймбуфер везде, ноль промежуточного диспетчера, ноль теневых буферов.

Мотивация (пользователь, 2026-07-22):
1. **Скорость.** Скролл/переход между комнатами (`ScrollPantalla` GS=9 → `drawRoom`)
   рисует ~704 тайла per-byte через диспетчер — тормозной.
2. **Память.** Теневой буфер `pat_shadow` (2КБ) сидит в плоскости p2; в 8-цветном
   движке p2 — отображаемая плоскость, эти 2КБ нужны под цветные спрайты A+/pre-shift.
3. **Чистота.** Литеральный ноль soft-VDP (пользователь выбрал полное удаление, а не
   прагматичный минимум — включая холодный диспетчер титула/звёзд/бонуса).

Побочный симптом для проверки: **демо обрывается почти в начале** (пре-существующее,
НЕ регрессия стриминга шрифта — билды со стримингом и без ведут себя кадр-в-кадр
одинаково). Гипотеза: связано с переходом между комнатами (`ScrollPantalla` двигает
героя демки). Диагностируется в Стадии 1.

## Инвентаризация остатков soft-VDP (текущий код, `grep -a` по сгенерированному asm)

| Потребитель | Расположение | Горячий? | Пишет в |
|---|---|---|---|
| Скролл `ScrollPantalla`→`drawRoom/2/3` | GS=9 (диспетч-таблица `dw ScrollPantalla`); `drawRoom`@6183, цикл 22×32 | **ДА, геймплей** | fb через `vw_name` |
| Титул `drawGameLogo`/`drawLogoRow` | L1208–2595 (буквы KING'S + пирамида) | нет (аттракт) | fb |
| Бонус-экран дверь/звезда/пирамида | L11835 (`DEtoVRAM_NXNY`), L11851/11893/11929 (`WRTVRM`) | полухолодный | fb |
| Загрузочный funnel `unpackGFX(set)`→`DEtoVRAM/fillVRAM`→`vec_vram_write` | загрузка уровня | нет | pat_shadow + mixbuf + spr_buf |
| `InviertePatron` | генерация зеркальных тайлов лестниц | нет (загрузка) | pat_shadow |
| Диспетчер `WRTVRM/RDVRM/vw_*/rv_*/SETWR/SETRD` + out-редирект + `vec_vdp_ptr` | ~180Б | — | — |
| Теневые буферы `pat_shadow`@0xC900 (**2КБ p2**), `mixbuf`@0x7E85 (120Б) | — | — | — |

Счётчики вызовов в сгенерированном asm: `WRTVRM`=7, `DEtoVRAM_NXNY`=2, `RDVRM`=1,
`fillVRAM`=1, `unpackGFX`=1, `unpackGFXset`=6.

Крайняя точка риска — **загрузочный funnel**: прошлая Stage-3-попытка (перевод паттернов
на нативный кэш) косвенно портила `mixbuf` → тайлы fg==bg → невидимы. Остальные
потребители пишут прямо в fb, от тени не зависят → безопаснее.

Ключевое ограничение верификации: **framebuffer/game-state сравнивать между билдами
НЕЛЬЗЯ** — «reseed» это frame-drop-coupling (медленный тик → пропуск VBLANK → `timer`
инкрем. по завершённым тикам → тайминг мумий сдвигается). Игра детерминирована по тику,
истинного RNG нет. Reseed переходный: при полной нативности (тик ≤ кадр, 0 дропов)
timer = счётчик кадров → reseed исчезнет сам.

## Архитектура решения — подход A (потребители → funnel → снос)

Инкрементально, каждая стадия: гейт + флаг отката + деплой на MiSTer (эталон
цвета/тайминга, cycle-accurate железо). Ценность рано (скролл), риск изолирован в конце.

### Стадия 0 — база и гейты
- Снапшоты канона: `base_canon.rom` (OFF) и `base_canon_8c.rom` (8C) — уже есть.
- **Гейтинг под `_8COLOR`.** Отгружаемый билд — 8-цветный (`base_canon_8c`). Нативные
  конверсии Стадий 1–4 включаются ТОЛЬКО под `_8COLOR` (+ свой `KV_NO_*` откат), поэтому
  OFF-билд (не-8color) остаётся **байт-в-байт с `base_canon.rom`** как незыблемый эталон
  того, что MSX-рекомпиляция не тронута. Общий код (`drawRoom` и т.п.) не переписывается
  на месте, а перенаправляется glue/флагом только в 8C-пути. OFF-база меняется лишь в
  Стадии 5 (физическое удаление диспетчера) — там ре-баселайн.
- Методология верификации (см. ограничение выше):
  - (а) `OFF==base` байт-в-байт — для стадий, добавляющих только vector-runtime без
    сдвига MSX-пути;
  - (б) `tools/verify/softvdp_cache_gate.js` — кэши (spr_buf/pat/mixbuf) байт-идентичны
    в точках загрузки (титул/уровень);
  - (в) пер-экранный визуал PNG (`vecrender.js`, конкретные кадры экранов);
  - (г) z80 logic-gate — тик расхождения с MSX;
  - (д) MiSTer каждый шаг (`sshpass scp` на 192.168.1.109, md5-сверка).

### Стадия 1 — нативный `drawRoom` (скролл/переход GS=9) [ГЛАВНАЯ ВЫГОДА]
- Заменить per-byte `vec_vram_write`-цикл `drawRoom3` на нативный тайл-блит из MapaRAM
  (шаблон `vec_nat_room`, уже нативный для статик-комнаты GS=4/5).
- Расследовать, кто зовёт `drawRoom` на пути перехода (`tickScroll`?), покрыть его.
- Диагностировать обрыв демо (связь с `ScrollPantalla`-переходом).
- Флаг `KV_NO_NATSCROLL`. Гейт: OFF==база (vector-only), визуал перехода, MiSTer
  (скролл плавный, демо не рвётся), logic-gate.

### Стадия 2 — нативный титул (`drawGameLogo`/`drawLogoRow`)
- Буквы KING'S VALLEY + пирамида: с `WRTVRM`→name на прямой fb-блит.
- Бонус: нативный контроль даёт раскраску титра под оригинал (COLORES_LOGO, отложенная
  просьба) — данные логотипа кодируют idx4/6/14, красим палитрой близко к оригиналу.
- Флаг `KV_NO_NATLOGO`. Гейт: визуал титра (буквы целые, цвет ближе к оригиналу), OFF==база.

### Стадия 3 — нативный бонус-экран (межуровневый reward)
- Дверь (`DEtoVRAM_NXNY` L11835) + звезда/пирамида-заливка/диагональ (`WRTVRM`
  L11851/11893/11929) → прямой fb-блит.
- Флаг `KV_NO_NATBONUS`. Гейт: визуал бонус-экрана, OFF==база.

### Стадия 4 — нативный загрузочный funnel [РИСК]
- `unpackGFX(set)`→`DEtoVRAM/fillVRAM` паттернов/цветов → нативная распаковка-в-кэш
  (шаблон `vec_spr_load`: RLE прямо в кэш, без VDP/funnel).
- **systematic-debugging** для бага mixbuf: трап записей в `mixbuf` (0x7E85) gold vs cand,
  лог PC — найти расходящегося писателя (гипотеза памяти: `vec_col_store` зависит от
  состояния/порядка, что ставил ОРИГ pat-путь `vw_wcol`).
- Эвакуирует `pat_shadow` из p2.
- Флаг `KV_NO_NATLOAD`. Гейт: `softvdp_cache_gate.js` (кэши идентичны в точках загрузки)
  + визуал + MiSTer.

### Стадия 5 — снос диспетчера + теней [финал]
- Удалить: `vec_vram_write`, `RDVRM`, `WRTVRM`, `vw_*`, `rv_*`, `SETWR`, `SETRD`,
  `DEtoVRAM(_NXNY)`, `fillVRAM`, out-редирект (py~1014/3176), `vec_vdp_ptr`,
  `InviertePatron`-путь.
- Удалить теневые буферы: `pat_shadow` (2КБ p2 свободны), `mixbuf` (120Б).
- Сузить `HideSprites` (больше не чистит регион pat_shadow).
- Здесь OFF-база меняется (удаляем общий код) → **ре-баселайн**; гейт = визуал ВСЕХ
  экранов + logic-gate + полный прогон на MiSTer. Откат — через флаги прошлых стадий
  (до-удалительное состояние).

## Результат и что разблокирует
- Ноль soft-VDP; нативный блит везде.
- Освобождено: **2КБ p2** (pat_shadow) + 120Б (mixbuf) + ~180Б кода (диспетчер) +
  out-редирект.
- Разблокирует (отдельным планом, НЕ в этой спеке): цветные спрайты A+ (фон p0/p1,
  спрайты p2/p3) и/или pre-shift-движок (RENDER −25%).

## Границы (что НЕ входит)
- Использование освободившихся 2КБ p2 (цвет A+/pre-shift) — отдельный план.
- POP-движок ускорения блита — отдельный план.
- `vec_spr_buf` (спрайт-кэш) НЕ трогаем — это легитимный нативный кэш, не soft-VDP тень.

## Риски
- Стадия 4 (funnel) — главный: mixbuf-косвенная порча. Митигируется systematic-debugging
  + cache-гейтом до reroute.
- Стадия 5 (снос) ломает `OFF==base` байт-гейт → нужен новый эталон + опора на визуал/
  logic-gate/MiSTer.
- Code-shift: Фаза S (символьная релокация кэшей в p3) уже сняла хрупкость сдвига кода —
  добавление/удаление кода больше не роняет старт. Проверять GS5-достижимость каждый шаг.
