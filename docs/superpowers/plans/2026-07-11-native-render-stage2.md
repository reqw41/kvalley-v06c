# KV нативный рендер — план Этапа 2 (asm в ROM + удаление soft-VDP → flicker-free)

> **Для исполнителя:** каждая задача = сборка + honest-рендер + сверка с ПРОТОТИПОМ Этапа 1
> (native_room_proto/native_spr_proto = эталон верных пикселей) + бюджет + long-run (GS=5 через
> memory.read, SP цел). Спек: `docs/superpowers/specs/2026-07-11-kv-native-render-engine-design.md`.

**Goal:** Перенести валидированный прототип в ROM: нативный рендер из game-RAM, удалить soft-VDP
(освободить память), спрайты в p2,p3 → **flicker-free прямо в игре**, при сохранённой логике.

**Architecture:** p0,p1=отрисованный лабиринт (раз/комнату+инкремент копания), p2,p3=спрайты
(erase+draw/кадр). Графика (паттерны/цвета) в main RAM (буферы), заполняются узким перехватом
loadGameGfx. glue подменяет setupRoom/drawRoom/updateSprites нативными; логику не трогаем.

## Global Constraints

- Читать game-RAM ТОЛЬКО через `memory.read` (банкинг). grep .asm/.lst с `LC_ALL=C`/`-a`.
- Вектор-пиксель = **2 bmp-пикселя по горизонтали** (из Этапа 1). Палитра MSX index=цвет TMS9918.
- Эталон верных пикселей = ПРОТОТИП Этапа 1 (native_*_proto.js), НЕ soft-VDP (у него компромиссы).
- Z80-мнемоника (sjasm 0.39). В SP-хайджеке (POP) НЕЛЬЗЯ call/push; восстанавливать SP.
- После КАЖДОЙ задачи: сборка → honest-рендер → long-run ≥2000 кадров (GS=5, SP норма) → бюджет.
- НЕ трогать логику (chkControls/физика/ИИ/tickMain). Убрать спрайт-флик оригинала (offsetPlanoSpr).
- База: чекпоинт `7bc1624`. Адреса/форматы — из спека (раздел «Графика»/«Этап 2»).

### Задача 2.1: СНЯТА — отдельные буферы НЕ нужны (реализация при старте 2.1, 2026-07-11)

**Причина:** (1) банки паттернов/цветов ИДЕНТИЧНЫ (used-тайлы 40/40) → нативный рендерер читает
**bank0 существующих теней** напрямую (`vec_pat_shadow+tile*8`, `vec_col_shadow+tile*8`, `vec_spr_
shadow+pat*8`) — так и делал прототип Этапа 1. (2) Отдельные буферы РЯДОМ с тенями не влезают:
тени ~14К в p2+p3, +6К буферов = 20К > 16К. Буферы «появляются» только КОГДА тени убираются
(bank0 остаётся) — это Задача 2.5 (сжатие теней до 1 банка = nat_pat/nat_col). До тех пор native-
рендер читает bank0 теней. **Никакого отдельного перехвата loadGameGfx не требуется.**

### Задача 2.2: АТОМАРНАЯ замена фон-рендера (soft-VDP фон OFF + нативный фон ON, p0,p1)

- [ ] Шаг 1: vec_nat_room: цикл 22×32 по MapaRAM(ProtaRoom*32+row*96+col)→getTileFromID→
      vec_pat_shadow+tile*8 (bank0!) + vec_col_shadow+tile*8 → блит 8 строк в p0,p1 (2 бита/плоскость
      по палитре 0.3). Гориз ×2. + vec_nat_cell (1 клетка).
- [ ] Шаг 2: ОТКЛЮЧИТЬ soft-VDP-фон: gate вызовов vec_blit_tile/vec_compose (не удалять код).
      glue: `setupRoom`→`call vec_nat_room` (+ сохранить updateSprites). Спрайты пока soft-VDP в
      p0,p1 (временный clash — ок для этого шага).
- [x] Шаг 3: DONE (субагент+моя проверка) — vec_nat_room рисует лабиринт из MapaRAM в p0,p1 через
      vec_blit_tile (под DI+isr_depth). Убран scan/compose/td_mark (code<0x6B00: 0x698B). HUD жив.
      GS=5, long-run стабилен, ФИЗИКА ГЕРОЯ ИДЕНТИЧНА (не ускорился). Дифф логики 77/200 = фаза
      врагов/интро (интро быстрее без scan), benign. Цвета = soft-VDP (жёлтый, vec_blit_tile) — тюн позже.

**КРИТ-НАХОДКА (попытка 2.2, 2026-07-11): CODE-SPACE СТЕНА.** Код+рантайм кончается на ~0x6AA3,
а game-переменные (MAP) начинаются с **0x6B00** (GameStatus). Свободно всего **~93 байта**.
vec_nat_room (~100+Б, даже переиспользуя vec_blit_tile) ПЕРЕШЁЛ 0x6B00 → затёр GameStatus/Vidas/
sprAttrib → GS=0x12 мусор, экран пуст, SP runaway. ДОБАВИТЬ код нельзя без освобождения.
ГРАБЛИ ПОПУТНО: vec_blit_tile использует SP-хайджек (POP-блит) — вызывать ТОЛЬКО под DI + с
isr_depth!=0 (иначе blit делает ei); из главного потока (setupRoom) обязателен di-guard.
**ВЫВОД: 2.2 НЕЛЬЗЯ «добавить native рядом с soft-VDP» — нет места. Нужен АТОМАРНЫЙ swap:
удалить код soft-VDP-фона (scan/compose/vec_td_mark/name-blit — освобождает место) И добавить
vec_nat_room в ОДНОМ шаге (net-neutral по размеру). Это = слияние задач 2.2+2.5.** Откачено к
df68068 (рабочий, GS=5 кадр 711). Альтернатива под место: сдвинуть MAP 0x6B00→выше (но MapaRAM
0x7560+0x8A0 упрётся в рантайм-ячейки 0x7E00 — тесно) ИЛИ ZX0-сжать код.

## Релокация теней (освобождение p3) — ДЕЛЕГИРОВАНО СУБАГЕНТУ (2026-07-11)

Освобождение p3 (0xE000-0xFFFF) под моно-спрайты требует сжать pat/col_shadow до 1 банка (банки
идентичны, 40/40) + перенести все тени p3 в p2 — мультисайтовая деликатная правка. Поручено
субагенту в изолированном worktree с жёстким gate: рендер BYTE-IDENTICAL (honest pixel-diff=0) +
long-run GS=5. Если субагент не добьётся byte-identical — не мержим. Результат = вход для Задачи 2.3+.

## Открытые вопросы / риски

- **Память (2.0) — критично:** влезут ли ~7К буферов в main RAM после удаления кода soft-VDP.
  Если нет — уменьшить (1 банк паттернов если совпадают? только used-тайлы?) или ZX0-сжатие кода.
- HW-скролл ScrollPantalla (2.7) — портировать логику скролла Вектора (порт 3).
- Тайминг: нативный рендер быстрее → игровой тик привязан к кадру, не должен ускоряться. Проверять
  скорость игры (не «быстрее оригинала»).
- Многокомнатность (ProtaRoom 0-2): смена комнаты = перерисовать фон (vec_nat_room) для новой комнаты.
