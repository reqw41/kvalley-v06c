# План: разблокировка скорости через символьную релокацию памяти

Дата: 2026-07-21. Цель: снять code-shift хрупкость (любой сдвиг кода роняет старт), чтобы
можно было ДОБАВЛЯТЬ код (pre-shift, render-list, цвет мумий) без derail. Это фундамент под
[[project_kv_pop_engine_plan]] Фазу 2/3 и спрайт-фиксы.

## Диагноз (подтверждён кодом + субагентами)
Хрупкость — НЕ тайминг (инструкции/такты при сдвиге те же, 6670/кадр), а **АДРЕСА**:
1. **Фикс-equ, на которые завязана логика**: `vec_spr_buf=0x6598`, `vnsx_mir=0x6B77`, `pat_maze_cell=0x6898`,
   `pat_font_cell=0x7D05`, mirror `_MIRON @0x63F8`, zero-page scratch — вбиты руками ради упаковки
   всего в low-RAM 0x0100-0x6B00 (перед game-vars). Добавить код → всё едет → кэши налезают на
   game-vars/друг друга → derail.
2. **Page-aligned LUT + вычисл.переходы** (`vec_revtab ALIGN 256`, `ld h,vec_revtab>>8; ld l,byte`;
   `jp (hl)`) — код напихан в pre-align padding ради экономии; переполнение padding двигает границу.
3. **HideSprites чистит 0xC000-0xFFFF** — мешает держать данные в p3.

Итог: символьный рефактор (метки вместо хардкод-адресов + перенос кэшей в СВОБОДНУЮ p3 8КБ)
делает раскладку релокация-толерантной → ассемблер сам пересчитает всё при сдвиге.

## Фаза S — символьная релокация (разблок; сама по себе 0 нового поведения)
**S1. Аудит хардкод-адресов.** Найти все абсолютные адреса в генерируемом коде (фикс-equ,
`ld sp,nnnn`, `jp nnnn`, self-mod ячейки `label equ $+1`). Перечень для конверсии в символьные метки:
`vec_spr_buf`, `pat_maze_cell`, `pat_font_cell`, `vnsx_mir`, mirror-cache, revbuf, zero-page scratch.
Критерий: значения equ вычисляются от МЕТОК (напр. `vec_spr_buf: equ end_of_code`), не константы.

**S2. Перенос кэшей low-RAM → свободная p3 (8КБ @0xE000).**
- `vec_spr_buf` (768Б), `pat_maze_cell` (608Б), `pat_font_cell` (384Б) → в p3 (0xE000+). Освобождает
  ~1.7КБ low-RAM (0x6598-0x6B00) под КОД.
- p3 схлопнута (невидима) → данные там невидимы, но CPU читает норм (RAM). Блит читает кэш из
  0xE000 — работает.
- **HideSprites**: в 8-цв спрайты идут в p0/p1/p2, p3 НЕ рисуется → HideSprites НЕ должен чистить p3
  (там кэш-данные). Правка: сузить его clear на p2 (0xC000-0xDFFF), p3 не трогать. Тогда кэш в p3
  переживает смену комнаты. (Или регенерить кэш per-room после clear — запасной вариант.)
- Порядок загрузки: UnpackPatterns/vec_spr_load пишут кэш ПОСЛЕ HideSprites (на входе в комнату) —
  проверить, что не затирается.

**S3. Расхардкод `_MIRON`/mirror @0x63F8** → символьная метка; снять assert точного адреса.

**S4. Гейт релокация-толерантности**: после S1-S3 добавить N байт dead-padding в vec-рантайм →
собрать → **ДОХОДИТ до GS5 (не роняет старт)**. Это доказывает, что сдвиг больше не derail'ит.
Также OFF==base, KV_8COLOR визуал не изменился (чистый рефактор адресов).

## Фаза P — pre-shift (теперь код влезает, память в p3 есть)
P1. Генератор pre-shifted (8 сдвигов × 13 hero+momia паттернов = ~5КБ) в p3 @0xE000+, per-room.
P2. POP-блит спрайтов: чтение pre-shifted (без rotate/mask/spill/edge) → shift-draw −45%, RENDER −25%.
P3. Гейт: block_equiv (логика), spr_blit_equiv (пиксели == on-the-fly), frame_budget RENDER↓, MiSTer.

## Фаза F — спрайт-фиксы (разблокированы освободившимся ROM/тактами)
F1. **HUD render-list** (save-under `vec_su_*`) — УЖЕ написан+доказан (unit-тест), теперь есть ROM.
F2. **Флик** — вынести/синхронизировать спрайт-блит (svofski VBlank) в освободившемся бюджете.
F3. **Цвет мумий по типу** (tiposMomia) — отдельный спрайт-слот появляется когда есть место под routing.

## Порядок ценности / риск
S — фундамент (без нового поведения, чистый рефактор адресов; гейт S4 доказывает разблок). Риск:
средний (аудит хардкодов кропотлив, но каждый шаг верифицируется honest_diff=0/GS5). P — главный
выигрыш скорости. F — качество (HUD/флик/цвет). БЕЗ S ничего из P/F не встаёт (доказано).

## Верификация (общая)
- Каждый шаг S: собрать, cmp OFF==base, KV_8COLOR доходит GS5, honest_render визуал не изменился.
- S4 dead-padding тест = ключевой гейт разблока.
- P/F: block_equiv + frame_budget + визуал + MiSTer.
- Флаги отката на каждую фазу.
