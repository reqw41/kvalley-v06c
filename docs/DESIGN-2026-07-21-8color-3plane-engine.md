# План: 8-цветный движок на 3 плоскостях (Old Tower техника) для KV

Дата: 2026-07-21. Директива пользователя: перейти на 8 цветов в 3 плоскостях, техника OldTower.
Эталон: `docs/reference/OLDTOWER_ANALYSIS.md`, `docs/reference/COLOR_MAP.md` (нужные цвета).

## Цель
Полноцветная картинка (фон + спрайты КОМПОЗИТ) в **3 плоскостях (p0/p1/p2) = 8 цветов**;
**4-я плоскость (p3, 0xE000-0xFFFF, 8КБ) СХЛОПНУТА в палитре** (её бит не меняет цвет) → свободна
под **pre-shifted спрайт-данные + render-list** (OldTower). Даёт: разноцветные мумии, кирпичи по
уровням в родных цветах, многоцветные сокровища, полная раскраска карты — всё, что теряет текущий
4-плоскостной A+ (см. COLOR_MAP §4.4).

## Раскладка плоскостей и палитры
- idx = (p0≪3)|(p1≪2)|(p2≪1)|p3. **p3 схлопнут**: `color[idx] == color[idx|1]` ∀idx (idx0==idx1,
  2==3, …) → 8 РАЗЛИЧНЫХ цветов от (p0,p1,p2) = чётные индексы 0,2,4,6,8,10,12,14.
- Видеоконтроллер сканирует p3 (безвредно), CPU держит там pre-shift-данные (8КБ).
- Палитра пишется в VBlank (латч по кадру), 8 значимых цветов (дублировать чёт=нечёт).

## Бюджет 8 цветов (общий фон+спрайты — ТЕСНО, нужен пер-экранный/пер-уровневый набор)
Кандидаты одновременно в геймплее: void(чёрн), кирпич-цвет-A, кирпич-цвет-B(по уровню),
лестницы, гем(+искра), кожа героя, одежда/белый, мумия-цвет. ~8 — впритык. Решения:
- Пер-УРОВНЕВАЯ смена кирпичей (ChgStoneColor scheme, C-субагент уже сделал логику) освобождает —
  кирпич-цвет один слот, меняется по уровню.
- Мумии: цвет по типу (tiposMomia, COLOR_MAP §3.2) — делят слот(ы) спрайтов; разные типы = разные
  слоты, но одновременно на экране 2-4 мумии → 1-2 цвета мумий в наборе.
- Гем-искра — покадровая палитра (как сейчас vec_brillo_pal).
- На СТАТИКЕ (карта/финал) — свой 8-цветный набор (карта: папирус/оранж-пирамиды/чёрн-линии/синий-GOAL).
Точное назначение 8 индексов — первый шаг реализации (таблица-раскладка на геймплей + на карту).

## Спрайты в 3 плоскостях (композит, OldTower render-list)
Спрайты рисуются В ТЕ ЖЕ p0/p1/p2 (не отдельная плоскость) → многоцветные (8 палитры). Стирание:
НЕ отдельная плоскость → нужно ВОССТАНОВИТЬ фон под спрайтом. OldTower-путь: **render-list** —
каждый кадр перерисовать фон-тайлы под спрайтами (footprint) + спрайты сверху. Pre-shift + POP-blit
делают это быстро. (Оценка B: +10-17%/кадр за стирание, но pre-shift shift-draw −45% компенсирует;
net по скорости ~нейтрально, выигрыш = ЦВЕТ.)

## POP-движок (из Фаз 0-2, переиспользуем)
- Interleaved данные по 3 плоскостям (p0,p1,p2 построчно), готовит генератор при загрузке комнаты.
- POP-blit: `ld sp,data; pop de; ld (hl),X; add 0x20; ld h,a` — шаг плоскости +0x20 в H (0x80→A0→C0).
- Pre-shifted спрайты (8 сдвигов × паттерн) в p3-хранилище (0xE000+), генерятся per-load.
- Page-aligned LUT (pat,shift→адрес; y→экран). Render-list putTile/drawSprites под DI.
- Фаза 1 доказала POP-blit 2.36×/тайл; Фаза 2 — clear −48%; переиспользуем машинерию.

## Фазы реализации (после сведения C-субагента; транслятор освободится)
1. **Палитра+схлопка p3**: 8-цветная палитра (чёт=нечёт), назначение 8 индексов (геймплей+карта);
   проверить на MiSTer, что бит p3 реально невидим при выбранных цветах.
2. **3-плоскостной POP-blit фона**: interleaved p0/p1/p2, POP-запись; honest_diff НЕ 0 (цвет изменился)
   — гейт = визуал ≈ COLOR_MAP + логика цела (block_equiv).
3. **pre-shift спрайты в p3**: генератор 8 сдвигов per-load в 0xE000+; render-list; композит в p0/p1/p2.
4. **Цвет по элементам**: кирпичи по уровням (из C), мумии по типу, сокровища 6 цветов, карта полная.
5. Гейты каждой фазы: визуал (honest_render + MiSTer), логика (block_equiv), флаг отката, замер RENDER.

## Риски
- 8 цветов ТЕСНО на всё сразу — нужен аккуратный пер-экранный набор (первый шаг).
- Схлопка p3 — железо-зависима (проверять MiSTer, не только эмулятор).
- Композит-спрайты возвращают стирание — render-list + pre-shift обязаны компенсировать; замерить.
- Major-рефактор блиттера — делать инкрементально с гейтами, флаг на откат к текущему A+.
- C-субагент (цвет в СТАРОЙ 4-пл. схеме) = stepping stone: логика кирпичей/карты переносится, но
  палитровые правки пересматриваются под 8-цвет.
