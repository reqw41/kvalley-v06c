# Задача: уменьшить мерцание KV1 приёмами из порта King's Valley II — без квазидиска

## Контекст

KV1 (этот репозиторий, живая линия — ветка `3p`, папка `3plane-composite25`) — ванильный Вектор-06Ц, без квазидиска.
Мерцание: луч догоняет пачку вывода спрайтов. Подробности — `docs/DESIGN-2026-08-20-flicker-vs-gorodetsky.md`:
у нас три прохода на объект («восстановить фон из блока → сохранить фон заново → вывести»), герой — два слота
(одежда/кожа), пачка ≈36 тыс. тактов против 10 тыс. у порта Городецкого. Лабиринт занимает все три видимые плоскости,
поэтому стирать нулями нельзя. История попыток — `docs/JOURNAL.md`, `docs/PLAN-2026-08-26-flicker.md`,
`docs/RENDER-2026-09-27-upper-flicker.md`. Закрыто, повторять не надо: композит в буфере (4 попытки),
кодогенерация пачки (cheap-gen), общий путь вывода без быстрых вариантов, двойной тик.

В порте King's Valley II (`~/projects/kvalley2-v06c`, только читать, ничего там не менять) мерцание ≈9 % кадров при
пороге 10 %, и в каждом таком кадре задето лишь несколько строк края спрайта, а не весь герой. Описание —
`docs/STAGE4.md`: §16 (вывод впереди луча — отвергнут), §18 (ускорение без потери темпа), раздел s4one в
`docs/JOURNAL.md` (один проход, порядок по лучу), cx_stutter в `docs/codex/stutter_report.md` (часы без потери IRQ).
Квазидиск там даёт заготовленные сдвиги и чистую копию фона (BGK). **У нас квазидиска нет** — переносим только приёмы,
которым он не нужен, или их варианты для ОЗУ.

## Приёмы KV2, которые нужно оценить и по возможности перенести

1. **Нет окна «стёрт, но не нарисован».** В KV2 спрайт выводится за один проход: для каждого байта поля пишется
   «фон + рисунок» сразу. Отдельно восстанавливается только полоска, которую новый кадр спрайта не закрывает
   (разница между старым и новым прямоугольником). У нас restore→save→show — три прохода, а между restore и show
   луч видит пустое место. Вариант для ОЗУ: фон под спрайтом брать не из сохранённого блока, а **из тайлов**.
   Фон KV1 — тайловый (карта комнаты + узоры тайлов MSX1 в ПЗУ), поэтому байт фона в любой точке вычисляется, и
   сохранять его не нужно. Это убирает проход save и сам буфер save-under: память освобождается, не тратится.
   Оцени цену вычисления фона по тайлам на байт против нынешнего restore+save. Учти три плоскости и восемь цветов:
   маска рисунка уже есть — гашение берёт тот же сдвинутый буфер.
2. **Восстанавливать только непокрытое.** Если старый и новый прямоугольники объекта перекрываются, перекрытую часть
   не стирать вовсе: её перезапишет новый вывод «фон+рисунок». Стереть нужно только освободившуюся полоску.
3. **Порядок вывода по лучу.** В KV2 объекты выводятся группами по Y сверху вниз вслед за лучом (s4one: мерцание
   16,3 → 7,0 % без потери темпа). Объект, который луч уже прошёл в этом кадре, выводится сразу, верхние — первыми.
   У нас есть beamwait/vbw_*; проверь, совместимы ли они с однопроходным выводом и не становятся ли лишними.
4. **Часы луча без потери прерываний.** KV2 cx_stutter: ожидание луча под DI теряло IRQ после оборота часов ВИ53
   (43 мс), темп музыки «плавал». У KV1 похожее разобрано в mus-jitter (`docs/JOURNAL.md`, 19.10). Сверь, что новый
   вывод не возвращает эту ошибку.
5. **Метрика мерцания по лучу в воротах.** В KV2 это доля кадров, где луч прошёл по строкам спрайта между стиранием
   и выводом (BEAM_MAX 10 %), и проверка «темп не хуже». У KV1 есть замеры bad_px/gone/spr_resid
   (`tools/verify/beam_*.js`, `spr_resid`). Сведи их в одни ворота с порогом и в отчёте покажи то же число до и
   после.

Если какой-то приём не окупается, дай число и брось его. Делать всё не обязательно; цель — заметно меньше мерцания.

## Ограничения

- Без квазидиска: ванильный Вектор, ПЗУ/кассета как сейчас. Память на нуле (свободно единицы–десятки байт до romCeil).
  Новое — только за счёт освобождённого: буфер save-under при восстановлении из тайлов, мёртвый код, слияние путей.
  Перед изменениями сделай опись занятости (по образцу `tools/mem/space.js` из KV2: область, размер, горячее или
  холодное).
- Темп и поведение — как сейчас (логика сверена с Z80, `tools/verify/lo_align.js` — equal), кадры на тик не хуже
  (natural/stress/tour), `snd_tempo` зелёный. Темп не догонять пропуском кадров вывода, только ускорять код.
- Порт 03 писать только на бордюре, клавиатуру опрашивать только в начале прерывания.
- Красные гейты базы (`spr_resid_gate`, `knife_purity`, `bonus_ending_gate` и что красно на старте) — перечисли в
  начале и не выдавай за новые; новых красных быть не должно.
- Эмуляторы — только без окна и без звука. На MiSTer не заливать: заливает владелец после приёмки.
- Работать в отдельном worktree от `3p`. Не делать push, не трогать другие ветки, `git push --all` запрещён.
