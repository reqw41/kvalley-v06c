# Аудит рендер-машинерии после переноса HUD (1.04b, 2026-08-13)

Задача-анализ по запросу владельца: «много времени потратили на тайминг и перенос
отрисовки — игра идёт неравномерно, возможно лишний код». Ни одна строка игрового
кода не тронута; инструменты — tools/verify/audit_*.js (10 шт., все падают на пустой
выборке). Сцены замеров: walk — пирамида 1; top — верхняя строка + прыжки;
mix — прогулка + нож + верх.

## 4. План по убыванию выигрыш/риск

1. **Фиксированный период шага (25 Гц)** — единственный рычаг ровности: смены
   45.9 → 4.5 % (walk); цена ~7–10 Б, 0 т; плата — скорость −18 % (25 против
   плавающих 30.6 Гц). РЕШЕНИЕ ВЛАДЕЛЬЦА: ровность против скорости.
   1-бис. Гистерезис (после промаха держать 2-кадровый период K шагов) — ~15–20 Б,
   промежуточный эффект, K подбирать замером.
2. **Удешевить холостые гейты vfr_gate + vec_su_fixup** (вместе 3055 т/шаг при
   96–99 % пустых): проверять vsu_any/vfr_need один раз на СЕРИЮ блитов. ~10–20 Б,
   полдня. 2-объектный шаг 61884 → ~58800: 54.2 % шагов начинают влезать в кадр.
   Это ускорение, не выравнивание.
3. **Сузить гейт topmask** (lo0>=224 → реальная зона эффекта lo0 229…239): ~5 Б,
   ~300–600 т/шаг у верха. Риск: побочный эффект vtm_zclip (гасит fb 240..255,
   фон там непуст в 1.04 % байт) — принимать top_overlap-гейтами.
4. **Вернуть fastmark/sortord/pr_scan из тика в пачку** (5092 т/шаг): пачка p90
   31428 → ~36500 при луче 15316. Риск ВЫСОКИЙ (мерцание верхних объектов),
   только после №1, мерить audit_bigbet + beam_tear/beam_color/hero_atomic.
5. **Резать подготовку (сдвиг+геометрия = 45.5 % дельты пика)**: предсдвинутые
   спрайты (места нет — квазидиск) или компилированный блиттер (отвергнут ранее).
   Недели, отдельный проект.

## 5. Что НЕ трогать

- Отложенная пачка и vsp_rdy — 96.1 % чистых объектов держатся на них.
- Пачка на вложенном прерывании — без неё каждый третий кадр без обновления.
- Порядок «стирание с конца vso_ord» — коммутативность доказана.
- Слитые пути vsb_*/vso_fastall — 38.5 % пачек, 48 т/байт.
- Стек-блит пары vpz_* — 922 продуктивных вызова из 1011.
- vclp — 660 реальных клипов.
- vsu_scw — 32 Б страховки (фон зоны нулевой только по сегодняшней компоновке).
- Детект частоты и vsnd_cdiv — ~9 т/кадр, спасают машины без ВИ53.
- tickInProgress — менять ПЕРИОД вызова, не флаг.
- Мёртвого кода нет.

Не покрыто: GS=9 (скролл комнаты) — ни одна сцена не воспроизвела; сцена с двумя
мумиями на непустом фоне — не существует в игре.
