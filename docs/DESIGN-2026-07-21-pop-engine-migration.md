# План: переход на POP-движок (OldTower-стиль) для KV Вектор-06Ц

Дата: 2026-07-21. Ветка: `plane-split-overwrite`. Эталон: `docs/reference/OLDTOWER_ANALYSIS.md`,
исходник OldTower (DenisGrachev), Rockman16 (экстремум), Exolon.

## 1. Зачем (обоснование замером)

Профиль пикового нагруженного кадра (`tools/verify/frame_budget_cats.js`, бюджет **59904 т/кадр**):

| Категория | Такты | % кадра |
|---|---|---|
| **RENDER (блит)** | **31732** | **53.0%** — узкое место |
| LOGIC | 8828 | 14.7% |
| OTHER | 7512 | 12.5% |
| AI_MOM | 6792 | 11.3% |
| AI_PRO | 3440 | 5.7% |
| MUSIC | 1040 | 1.7% |
| KNIFE | 516 | 0.9% |
| **ИТОГО** | **59860** | **99.9%** (потолок!) |

Мы упираемся в 99.9% кадра, узкое место — **блит спрайтов (RENDER)**. Наш блит тайла = **68 инстр**
(soft-VDP наследие), POP-движок = **~25 инстр** (pop de = 2 строки разом, все плоскости interleaved,
шаг плоскости +0x20 в H). Ускорение блита **~2.5–2.7×**.

**Прогноз с POP-движком:** RENDER 31732 → **~13000 т**; пиковый тик 99.9% → **~67% кадра** →
**~20000 т запаса**. Это (а) снимает с потолка (стабильнее fps) и (б) даёт бюджет под 8-цветный
фон / разноцветные мумии (стоимость ~6–10K т — влезает).

## 2. Техники POP-движка (из OLDTOWER_ANALYSIS.md §1)

```
    ld bc, 32*256+32*3     ; B=0x20 (шаг плоскости Вектора!), C=0x60 (откат)
    ld sp, tile_data       ; SP = указатель на interleaved данные тайла
    pop de                 ; 11т: 2 байта (плоскости 0,1 строки)
    ld (hl),e : add b : ld h,a   ; плоскость0 -> H+=0x20 -> плоскость1
    ld (hl),d : add b : ld h,a
    pop de
    ld (hl),e : add b : ld h,a   ; плоскости 2,3
    ld (hl),d
    sub c : ld h,a               ; H-=0x60 (назад в плоскость0), следующая строка
```

Ключи: (а) **данные тайла interleaved по плоскостям** (p0,p1,p2,p3 построчно) — готовит
PC-конвертер; (б) шаг плоскости Вектора = +0x20 в СТАРШЕМ байте (`add b/ld h,a` = 2 такта!);
(в) **page-aligned LUT**: y→адрес экрана, tile→адрес данных (0 арифметики); (г) **render-list**:
`putTile` кладёт запись с ГОТОВЫМИ адресами, `drawSprites` блитит всё под DI; (д) блоки
выровнены `org ($+255)&0xFF00`, вход по младшему байту.

## 3. Фазы (инкрементально, каждая с гейтом; НЕ ломать текущий рабочий вариант)

### Фаза 0 — PC-конвертер тайлов + LUT (фундамент, без изменения рантайма)
- Скрипт `tools/pop/tiles_to_interleaved.py`: KV-тайлсеты (уже распакованные паттерны) →
  interleaved-формат по плоскостям + page-aligned LUT (tile→data, y→screen).
- **Гейт:** конвертер воспроизводит текущие пиксели байт-в-байт (сверка с honest_render).
- Риск низкий: только офлайн-данные, рантайм не тронут.

### Фаза 1 — POP-блит СТАТИЧНОГО фона (вход в комнату, `vec_nat_room`)
- Заменить блит фона на POP (interleaved-данные + page-LUT). Рисуется РАЗ на комнату — низкий риск.
- **Гейт:** `honest_diff` фон = 0 (те же пиксели); `frame_budget_cats` — падение RENDER на входе.
- Флаг: `KV_POP_BG`.

### ★ РЕЗУЛЬТАТ Фазы 2 (2026-07-21) — ВЫИГРЫШ МОДЕСТ, БОЛЬШОЙ ПРИЗ MEMORY-BLOCKED
Профиль RENDER (пик, 4 спрайта): **shift-петли рисования 55%** (2811 т/полустолбец), **clear_box 24%**
(стирание prev), overhead 21%. Спрайты рисуются под ПРОИЗВОЛЬНЫМ X&7 → POP-interleave/pre-shift
НЕ байт-идентичен (нужен сдвиг), а 8× память под pre-shifted НЕ влезает (запас до vec_spr_buf=608Б).
Тик идёт с ПЕРЕ-включёнными прерываниями (nested sound-ISR) → SP-хайджек (как vbt_row) опасен в горячем пути.
**Сделано (флаг KV_POP_SPR, opt-in, default OFF):** развёрнут 16-строчный цикл clear (mov m,a=7т vs
ld(hl),0=10т, убран счётчик) → **clear −48%** (2229→1156 т/выз), байт-идентично (spr_blit_equiv 58/58=0).
На busy-кадре ~5000 т ≈ 8% бюджета. НО пик тика 99.9% визуально НЕ упал: frame-drop coupling заполняет
запас более активной траекторией (больше живых мумий→AI) — render-запас РЕАЛЕН, но маскируется.
**ГЛАВНЫЙ ОСТАТОК (55% RENDER = shift-draw) MEMORY-BLOCKED:** pre-shifted данные (сдвиг per-frame→per-load,
OldTower-стиль) требуют ~8× память спрайтов, не влезает. Разблокировка = освободить ~2-4КБ под pre-shifted
(напр. 2К p2 @0xC900 от map-direct, но это ВИДИМАЯ плоскость — нужен не-видимый регион). Диагносты:
sprite_blit_cost.js, spr_blit_equiv.js. ВЫВОД: KV-спрайт-блит УЖЕ тугой (shift-специализирован); POP даёт
модест без memory-рефактора. OldTower-скорости требуют pre-shifted данные = отдельный memory-этап.

### Фаза 2 — POP-блит СПРАЙТОВ (герой/мумии) — ГЛАВНЫЙ ВЫИГРЫШ
- Render-list (`putTile`/`drawSprites` под DI) + POP-блит спрайтов вместо текущего
  overwrite-блиттера. Это горячий путь (RENDER 53%).
- **Гейт:** `block_equiv` (логика тика идентична), визуальный рендер, `frame_budget_cats`
  RENDER ↓ (цель ~13K). Изоляция `KV_POP_SPR`.
- Риск: цикло-чувствительность (frame-drop coupling) — гейт по логике, не по тактам.

### Фаза 3 — POP-блит СКРОЛЛА (`drawRoom2`, GS=9) + mono-scroll
- Скролл на POP-блит (+ опционально одна плоскость во время скролла).
- **Гейт:** число кадров скролла ↓, визуально ок, геймплей honest_diff=0.

### Фаза 4 (опционально, на освободившемся бюджете) — БОЛЬШЕ ЦВЕТА
- 8-цветный фон (3 плоскости) на статичных экранах и/или разноцветные мумии — теперь влезает
  в ~20K т запаса (см. §1). Держать разделение спрайт-плоскостей (иначе возврат стоимости стирания).

- **★ РАСКРАСКА КАРТЫ «PYRAMID'S MAP» (между уровнями) как в ОРИГИНАЛЕ** (отложено пользователем
  до теста POP-движка, 2026-07-21). Сейчас карта рисуется ОДНИМ цветом переднего плана (idx8=золото)
  — пирамиды и линии слились в золотые полосы. Оригинал (скриншот MSX):
  - **папирус** = чистый БЕЛЫЙ (у нас кремовый idx12=0xFF — на MiSTer белее);
  - **пирамиды** = ОРАНЖЕВЫЕ 2-тон (светлый верх/тёмный низ, ≈ TMS 8/9 → Вектор 0x57/0x5F);
  - **линии-пути** = ЧЁРНЫЕ тонкие (idx0=0x00);
  - **GOAL** = СИНИЙ текст (0xD2) в ОРАНЖЕВОЙ рамке;
  - маленькая стрелка-указатель (◄) = уже есть (спрайт p3, пульсирует — наша добавка).
  Механизм: карта СТАТИЧНА и p2 СВОБОДНА (map-direct, p2sh=0) → 3-плоскостной 8-цветный фон ДЁШЕВ
  (разовая отрисовка). Блит карты должен ЧЕСТНО читать `colorTableMap` (msx ~10100, тайлы 0xC0-0xE7)
  и раскладывать per-tile цвет по p0/p1/p2 (пирамида=оранж-индекс, линия=idx0 чёрн, папирус=idx12 бел,
  GOAL=idx с синим). Сейчас порт `colorTableMap` ИГНОРИРУЕТ. Данные: `colorTableMap`/`gfxMap`
  (msx 10083/10100), палитра `vec_pal_menu`. Флаг KV_POP_MAPCOLOR. Гейт: визуальный (рендер ≈ оригинал)
  + геймплей honest_diff=0 (только карта) + p2sh на карте не растёт в видимую зону.

## 4. Память / раскладка
- Page-aligned LUT (y→экран, tile→данные) требуют выровненных таблиц — проверить бюджет low-RAM
  (сейчас: код 0x100-0x63FF, кэши 0x6598-0x6B00, vars 0x6B00-0x6F13, стек, MapaRAM 0x7313+,
  vec-runtime+font 0x7C13-0x8000). Interleaved-данные = тот же размер, что паттерны; LUT ~несколько
  page.
- p2/p3 частично освобождены map-direct (2К @0xC900) — под цветные спрайты/данные.

## 5. Верификация (общая)
- `tools/verify/frame_budget_cats.js` — RENDER до/после каждой фазы (главная метрика).
- `tools/verify/honest_diff.js` — байт-идентичность фона (Фаза 1) и геймплея (регресс-гейт).
- `tools/verify/block_equiv.js` — логическая эквивалентность спрайт-тика (Фаза 2).
- Визуальный `honest_render` + MiSTer после каждой фазы (эталон железа).
- Флаги отката на каждую фазу (KV_POP_*).

## 6. Порядок ценности
Фаза 2 (спрайты) = максимальный выигрыш (бьёт в 53% RENDER). Фаза 0 обязательна первой (данные).
Фаза 1 — безопасная разминка на статике. Фаза 3 — скролл. Фаза 4 — трата бюджета на цвет.
