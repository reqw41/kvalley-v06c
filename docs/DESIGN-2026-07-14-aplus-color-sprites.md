# Дизайн: A+ цветные спрайты (2+2 плоскости) для King's Valley / Вектор-06Ц

Статус: ПРОЕКТИРОВАНИЕ (2026-07-14). Продолжение [DECISION-2026-07-13-p2-evacuation](DECISION-2026-07-13-p2-evacuation.md).
Ссылки: память project_kv_color_sprites_plan, feedback_kv_msx_original_colors.

## Цель
Цветные спрайты как в оригинале MSX: **герой 2 цвета** (серый+тёмнокрасный),
**мумии 1 цвет**, нож — через раскладку **A+ = 2+2 плоскости** (фон p0+p1, спрайты
p2+p3), overwrite+clear_box (без save/restore фона, ~4000т/кадр). Экономика и палитра
уже подтверждены (см. память). НЕ вариант B (Exolon 3-плана, 8 цветов, ~25Гц) — он
дороже и требует стек-кэша; A+ ближе к 50Гц и флик-фри.

## Целевая раскладка

### Плоскости
| Плоскость | Роль A+ |
|---|---|
| p0 (0x8000) | фон, бит 0 |
| p1 (0xA000) | фон, бит 1 → **фон = 4 цвета** |
| p2 (0xC000) | спрайты, слой A |
| p3 (0xE000) | спрайты, слой B |

### Палитра (14 цветов, глобальная, приоритет спрайт-битов)
Из замера MSX→Вектор (память). 16 регистров:
- idx с p3=1 (8 шт) → **цвет-B спрайта** (напр. кожа героя 0x5F / мумия)
- idx p3=0 & p2=1 (4 шт) → **цвет-A спрайта** (напр. одежда героя 0xF6)
- idx p2=p3=0 (4 шт) → **фон** (4 цвета: void/кирпич/блик/лестница)
Итог: спрайт-биты доминируют → чистый цвет спрайта поверх любого фона, прозрачность
(p2=p3=0) показывает фон. Мумии 1цв: в p3→цвет-B, в p2→цвет-A.
ЗАСАДА (память): кожа героя idx6 и мумия-t3 idx8 схлопываются в 0x5F — развести t3→0x9F.

### work-RAM (дыра 753Б @0x680F-0x6B00) — впритык
Выносится фон-кэш: pat рабнабор (~552Б для 69 тайлов) + mixcol ужатый (~88Б для 11
mixed) = ~640Б. Резерв при нехватке: урезать раздутый стек (1517Б vs MSX 749Б).

## Компоненты (детали — после исследования a062ae/a34c45)

### 1. Вынос меню-лого на стрим-рендер — КРУПНЫЙ рычаг [РЕШЕНО a34c45]
Хвост 0x8c-0xff = тайлсет **меню King's Valley** (KING'S 0x9B-0xAC, VALLEY 0xAD-0xC6),
грузится раз при boot (`LoadIntroGfx`/`setGfxMenu`) и висит резидентно всю игру.
Konami-лого УЖЕ вынесено стрим-декодером `vec_kl_next`/`vec_kl_decode_tile` (py 588-744):
RLE→8-байтный скретч `vec_kl_scr`→прямо в framebuffer, **pat_shadow не трогает**. ГОТОВЫЙ
ОБРАЗЕЦ. Решение: перевести меню-лого (`GFX_Menu`, `drawGameLogo` :1040) на такой же
стрим-рендер → pat[0x8c-0xff] не нужен → освобождает хвост (~928Б pat + ~928Б col ≈1.8К).
Меж-уровень/финал (`drawMenuEnd` :1082, `GFX_PiramidLogo`) — тем же приёмом.

### 2. Компактный фон-кэш в work-RAM [РЕШЕНО a34c45]
Игровой тайлсет = **непрерывный 0x40-0x8b (76 тайлов = 608Б)** → влезает в 753Б дыру.
Индексация блиттера прямая `base+tile*8` с ЕДИНОЙ базой (`vbt_core` py 1209) → tile→slot
маппинг НЕ нужен, хватает биас-базы `(workram - 0x40*8)`.
Правятся 5 сайтов (одна константа `vec_pat_shadow` equ py 769, либо по месту):
- читатели: `vbt_core` (1209, главный), `vec_blit_brillo` (1513, гемы), `rv_patn`/RDVRM (1149, Flip при загрузке)
- писатели: `vec_de_ok` (1993, bulk распаковка), `vw_wcol` (1061, побайтный)
**РАЗВИЛКА (шрифт HUD 0x10-0x3f тоже течёт через vbt_core):**
- (реком) вынести HUD-шрифт нативно (как Konami-лого) → 0x40-0x8b хватает, без развилки в блиттере, чище
- либо tile-развилка в vbt_core/vec_blit_brillo: tile<0x40 → старый pat_shadow, ≥0x40 → work-кэш
- либо перенести 0x10-0x8b целиком (992Б — НЕ влезает в 753, нужен урезанный стек)
mixcol (0xD400, 512Б) ужать до реальных ~11 mixed (88Б), тоже в work-RAM.
NB: drawTile/drawCortinilla НЕ нативны, но name/dirty УЖЕ сняты (Фаза B: vw_name блитит
прямо через vec_text_blit→vbt_core); их тайлы 0x40-0x8b в кэше → перенос не ломает.

### 3. spr_shadow: частично резидент [РЕШЕНО a062ae — ТЕСНОТА]
`vec_spr_shadow` (0xC080, 2К, p2) — резидентный источник графики, читается `vec_nsx`
каждый кадр. Пишется `vw_spr` (soft-VDP 0x1800). Игра ДИНАМИЧЕСКИ регенерирует
hero-паттерны: `loadAnimation` (подбор pico/knife), `flipSprites` (зеркало влево).
- Статичные спрайты (мумии, двери) → **inline-компиляция из ROM**, буфер не нужен.
- Динамич. hero-паттерны → нужен буфер-приёмник. Решение: перехватить `vw_spr`/
  `loadAnimation`, писать hero-варианты в МАЛЕНЬКИЙ буфер (~128-256Б: текущие 2 hero-
  спрайта × левый/правый × 32Б) вместо 2К spr_shadow в p2.
⟹ spr_shadow из p2 убирается, остаётся мелкий hero-буфер (work-RAM/невидимая RAM).

### 4. Спрайт-блиттер A+ (overwrite p2+p3) [РЕШЕНО a062ae]
- **Герой 2 цвета БЕСПЛАТНО:** уже 2 наложенных 16×16 спрайта (sprAttrib entry4 одежда
  + entry5 кожа, паттерны d и d+4). Развести: entry4→плоскость-A, entry5→плоскость-B.
- **Мумия 1 цвет:** 1 спрайт → p2 (цвет-A) или p3 (цвет-B) по типу.
- Блиттер: `rot{s}_loop` (py 528-564, 8 петель суб-пикс. сдвига X&7) — заменить `xor(hl)`
  на `ld(hl),a` overwrite в p2 И p3 (p3-адрес = p2+0x2000, оба за проход). Приём Бориса:
  только цветные байты (inline выкидывает прозрачные). Стоимость шифт-блита (~24% покоя)
  растёт ×2 (2 плоскости) — но overwrite дешевле XOR-read-modify, нетто ~как сейчас.
- **Стирание:** нет готового clear_box. Написать НОВЫЙ на шаблоне `rot{s}_loop` (16 рядов
  `dec l`, 2-3 колонки `inc h`, `ld(hl),0` по footprint) для p2+p3. Снять XOR-самостирание,
  `vec_nsp_prev`-XOR и `vec_spr_flush`.

## БЛОКЕР: теснота памяти (выявлено проектированием)
p2 надо освободить ПОЛНОСТЬЮ (палитра сделает p2 видимой → любые тени = мусор).
Вынести из p2: pat 608Б + mixcol 88Б + spr_shadow (hero-буфер ~256Б после inline статики).
= ~950Б. work-RAM дыра = 753Б → **НЕ влезает** (~200Б дефицит).
Резервы: (1) урезать раздутый стек 1517→~800Б (после замера глубины) = +700Б → влезает
с запасом; (2) hero-буфер держать в освобождённом хвосте p2? — нет, p2 видима.
⟹ Урезание стека — обязательная часть A+ (замерить max-глубину стека, включая ISR/il-стабы).
Резерв последней линии: Exolon 3-план (color-clash, ~25Гц) — если теснота непреодолима.

## Порядок миграции (гейты каждого шага)
Гейты: logic_gate (clean N тиков vs MSX) + фон p0/p1 инвариант + короткий diff +
устойчивый покой + визуал PNG. (honest_diff=0 НЕприменим — cycle-sensitivity.)

**Фаза P — освобождение p2 (готовит, картинка не меняется, гейт = фон-инвариант):**
1. ✅ ГОТОВО (коммит 0d8d96f): замер реальной глубины стека = 120Б (реликт soft-VDP
   раздул до 1517Б). Урезано до 1024Б → освобождено ~513Б @0x7CFF-0x7F00 (между
   сдвинутыми vec_kl_* и vec_tilemode). Итого свободно work-RAM ~1266Б (дыра 753Б
   @0x680F-0x6B00 + новая 513Б). Гейты: logic clean 1600, запас стека 904Б, визуал цел.
2. ~~Вынос меню-лого стрим-рендером~~ ОТМЕНЁН/упрощён (2026-07-14): меню King's Valley
   цветное+позиционное (COLORES_LOGO/ATTRIB_Menu, drawGameLogo KING'S 0x9B-0xAC/VALLEY
   0xAD-0xC6/GFX_PiramidLogo) — стрим-рендер дорог. ВМЕСТО: палитра защёлкивается по кадру →
   МЕНЮ держит свою палитру (p2 невидима, меню не трогаем), ГЕЙМПЛЕЙ — A+ палитру (p2 видима).
   Меню-тайлсет в p2 стирается clear'ом p2 при входе в комнату (clear всё равно нужен для
   overwrite-спрайтов). Хвост 0x8c-0xff трогать НЕ нужно. Шаг растворяется в палитра-стратегии (шаг 5).
3. Фон-кэш: pat[0x40-0x8b] (608Б) + mixcol (88Б) → work-RAM; HUD-шрифт 0x10-0x3f вынести нативно (убирает развилку в блиттере). Очистить pat/col-области p2.
4. spr_shadow: inline статику (мумии/двери), hero-буфер ~256Б в work-RAM; очистить 0xC080. p2 полностью пуста.

**Фаза A+ — цвет (картинка МЕНЯЕТСЯ, гейт = визуал+logic+покой):**
5. Палитра A+ (14 цветов, приоритет спрайт-битов, t3→0x9F); p2 становится видимой; фон 4 цвета.
6. Спрайт-блиттер overwrite p2+p3: герой 2 наложенных спрайта → 2 плоскости; мумии 1цв; clear_box вместо XOR; inline.
7. Визуальная доводка цвета под оригинал MSX (палитра-байты из памяти).

## Открытые вопросы закрыты (a062ae + a34c45). Остаточные риски:
- Теснота work-RAM (~200Б дефицит) снимается урезанием стека (шаг 1) — критический путь.
- Стоимость шифт-блита ×2 плоскости — проверить бюджет после шага 6 (профиль покоя).
- Динамич. hero-паттерны через vw_spr/loadAnimation — самый тонкий кусок (шаг 4).
