### Что именно измерено и как замыкается учёт

Один шаг части А — внешний ISR, в котором действительно началась логика: от кадрового запроса до RET внешнего ISR. Время ожидания принятия IRQ входит в шапку отдельным полем request_wait; аппаратный DI/RST7 учитывается по реализации tv.js. Цена инструкции берётся из cpu.vcycles после исполнения; классификация сделана по активной глубине ISR и входу/возврату процедуры (PC + возвратный адрес + SP). Дочерние CALL/JP остаются в контексте процедуры; вложенный IRQ создаёт отдельный контекст и не оплачивается второй раз подготовкой или runGame.

Независимый контроль — развёрнутая растровая координата после фактического выхода из ISR. Проверяются и сумма инструкционных статей против CPU-времени, и та же сумма против растрового времени. Суммировать медианы разных статей нельзя: замыкание проверено на каждом сыром шаге. Все шаги лежат в results.json.

Длинный шаг: разность номеров видеокадров между фактическими стартами логики ≥ 3; разность ровно 4 выделена отдельно. Кадр: **59904 тактов**. interval_frames — разность номеров видеокадров фактических стартов, без округления длительности; точные interval_cycles и interval_frames_fractional сохранены. Для последнего шага драйвер дренируется до следующего старта с тем же вводом; метрики исторического baseline не включают дренаж.

Внешние ISR без запуска логики не принадлежат окну «запрос→RET логического ISR». Они сохранены отдельно в nonlogic_external_isrs. Чтобы их стоимость не исчезла, для каждого шага дополнительно замкнут полный интервал старт→следующий старт: interval_articles включает эти ISR, вложенные IRQ и ожидание MAIN. Именно по этому интервалу распределена экономия сейва на шаг.

Границы: vso_fix включает vec_spr_out и хвост починки vfr_gate; учтены все текущие писатели через memory.write в трёх видимых плоскостях. Подготовка начинается на vec_nat_sprites и заканчивается записью vsp_rdy=1; при раннем выходе — реальным возвратом. Её дочерние функции учтены эксклюзивно. Внешний звук до пачки входит в шапку; служебный звук tickMain/кооперативный звук — в диспетчеризацию. «runGame» в статье 3 включает вызываемые им фоновые блиты, но не подготовку и не служебный звук: это не только AI. Статья 6 также содержит chkControls и пролог tickMain, чтобы ни один такт не остался вне заданных статей.

## Гипотезы

### Цена частичного сейва: модель, не выполненная оптимизация

Стоимость инструкций взята из того же i8080-ядра на отдельном пустом microbenchmark CPU; загруженный игровой ROM не меняется. На Векторе POP DE стоит 12, MOV M,E / INR L / MOV M,D / INR L — по 8. Полный развёрнутый сейв: (12 + 8 + 8 + 8 + 8) / 2 = **22 такта/байт**.

Перенос внутри слота: MOV A,M + STAX D + INX D + INR L = 32 такта/байт; развёртка на четыре байта добавляет (DCR C + JNZ)/четыре = 5, итого **37**. Та же форма уже есть у vsm_p2u/vsm_p2d. Петля переменной длины для края: MOV A,M + STAX D + INX D + INR L + DCR C + JNZ taken = **52**. Даже оптимистический перенос POP-ядром стоит не меньше полного сейва на тот же байт.

Накладные полного save для каждого события: F − 22×N, где F — реальный эксклюзивный профиль процедуры, N — реально прочитанные байты. Они сохраняются у частичного пути, включая шапку слота и инвалидирование ZFLAG; пропускается только тело повторного чтения. Геометрические проверки: 8 × (LDA + LXI H + CMP M + JNZ taken) + CALL + RET = **420** тактов. Проверка пересечений дополнительно оплачивается на каждого другого участника явной последовательностью полевых сравнений; стоимость лежит в model.intersection_check_cycles. Это консервативный эскиз, а не доказанный минимум. Проверки early-exit и будущая сборка могут изменить цену.

Формулы: общий байтовый участок O, новые края E, перемещаемые байты M. Если физический габарит не изменился, M=0 и E=0, данные остаются на месте. Иначе M=O. Цена частичного пути = накладные полного save + геометрические проверки + цена переноса×M + цена чтения×E + setup столбцов. Restore не сокращается: порядок очистки и общий фронт сейвов остаются прежними.

Вариант «перенос+края» — геометрическая оценка без проверки пересечений, **не безопасный путь**. Вариант с отказом — полный save при invalid, смене ширины/плоскостей, пересечении, завороте или отсутствии общего участка; проверки оплачиваются и при отказе. Оптимистический столбец — только нижняя оценка цены байтового ядра, не вариант для реализации. Частичный перенос уже существует в vsm_ph3 слитого пути; здесь моделируются только реально исполненные полные save, а не повторное добавление этой оптимизации.

Предельная цена проверок — полный save минус цена переноса/краёв без геометрических проверок. Отрицательный предел означает, что перенос не окупается даже при бесплатных проверках. Для положительного предела будущий код обязан проверить всё дешевле этой суммы.

Классы взаимоисключающие: сначала пересечение, затем смена ширины/числа плоскостей, затем горизонтальное/вертикальное движение и стояние; остальные — комбинированные случаи/смена плоскости. Движение учитывается по старым координатам vec_nsp_prev и новым координатам записи вывода, поэтому движение внутри одного байтового габарита не записывается ошибочно в стояние.

### Вывод

На стрессовых длинных шагах самая дорогая статья — **4. Подготовка спрайтов/списка**, среднее **70974.87**, медиана **72572** тактов. Это измеренный приоритет для следующего анализа. Внутри подготовки первым смотреть vec_spr_prep: геометрия, сдвиги и буферы.

В смешанном обычном прогоне на длинных шагах по среднему крупнейшая статья — 3. runGame без подготовки/сервисного звука (72075.27 тактов); в игровом участке GS=5 — 4. Подготовка спрайтов/списка (52393.84 тактов). Переходы экранов нельзя использовать как аргумент переписывать AI.

Предложенный общий частичный сейв **не окупается в консервативном оценочном варианте с проверками**: на стрессе медиана экономии на пачку **-2976** тактов, в обычном прогоне среднее на пачку **-1166.56**. Возможный более узкий кандидат — сохранение уже правильного слота при неизменном физическом габарите и дешёвом доказательстве свежести. Это отдельная гипотеза: её цену и отсутствие следов ещё надо проверить. Планировщик и композит остаются отложенными.

Никакой новой отрисовки не выполнялось; число дефектных верхних кадров для гипотетического пути не измерялось. Из экономии тактов нельзя выводить устранение мерцания. Принятых изменений игры нет.
