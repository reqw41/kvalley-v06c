### 2. vec_spr_prep по вызовам и объектам

### Повторное использование подготовки

Ключ из задания: (кадр, X-фаза, зеркало, число плоскостей). Отдельно проверены источник/ширина и фактическое совпадение полученного буфера; payload-хеш вычислен офлайн и не считается бесплатной проверкой будущего игрового кода. ### Что можно снять в save/restore

Предельная экономия mask_bytes касается только байтов, которые в том же restore затем перекрывает копия сохранённого фона. Подсчитаны адреса и порядок, а не просто число вызовов. Удаление всей ANDN-петли требует доказать хвосты, клип и отсутствие зависимости промежуточных читателей; индивидуальное удаление записей не автоматически снимает всё управление циклом. Inline vec_su_ptr оценивает только CALL+RET у остающихся реальных вызовов и увеличивает код. Порядок restore→save→вывод в этих оценках сохраняется.


| История | Что здесь отличается |
| --- | --- |
| 21.09: skip-restore без slb | Restore сохраняется; рассматривается только маска, перекрытая внутри того же вызова. Хвосты должны остаться. |
| 21.09: save-only strip / LAST / skip мумии | Ни сейвы, ни фоновые слоты не пропускаются и порядок LAST не меняется. |
| 21.09: self-mod / занятой scratch / переполнение | Эмуляторный наблюдатель не меняет игровой код и scratch. Cache-RAM лишь оценён, не выделен. |
| Этап 2: повторные vec_su_ptr | Удаление повторных вычислений уже внесено. Новая оценка считает только CALL+RET реально оставшихся вызовов; прежнюю экономию второй раз не считает. |
| Этап 3: vsa_row unroll | Развёртка уже есть. Оценивается устранение ненужного ANDN, а не повторная развёртка. |
| 27.09: отложенные restore/save LAST | Отложенного стирания или заражающего сейва мумии нет; всё остаётся на штатных местах. |
