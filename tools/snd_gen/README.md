# snd_gen — потоки звука ВИ53

Игра поддерживает только ВИ53. Драйвер Konami (разбор нот, огибающие, микшер AY, оверлей WRTPSG,
`vec_ay2vi`) заменён проигрывателем готовых потоков событий (`src/v06c/vec_snd.asm`). Этот каталог —
сборочный шаг, который делает потоки.

## Что здесь

| файл | назначение |
| --- | --- |
| `base_e2b8f32.rom`, `.sym` | замороженная сборка основы (e2b8f32) с исходным драйвером Konami и его нотными данными |
| `capture.js` | прогоняет исходный драйвер в эмуляторе vector06js (режим ВИ53) и снимает состояние трёх каналов после каждого тика звука для каждого звука игры; результат — `captured.json` |
| `captured.json` | съёмка (закоммичена) |
| `encode.js` | чистая функция: съёмка → потоки байт; формат потока описан в шапке файла |
| `snd_gen.js` | всё вместе: съёмка (по `--recapture`) → потоки → проверка моделью проигрывателя против съёмки на каждом тике → `src/gen/snd_streams.asm`, `src/gen/snd_streams_far.asm` |
| `layout.json` | `{"far": [...]}` — какие потоки уносит за выровненные таблицы (зазор `.align`, см. ниже) |

## Как сборка использует результат

`build.sh` генератор **не вызывает**: нужен эмулятор, а результат детерминирован. В репозитории лежат
готовые `src/gen/snd_streams.asm` и `src/gen/snd_streams_far.asm`, их включают `vec_snd.asm` и
`kvalley_8c.asm`.

## Как перегенерировать

Нужно только если менялись нотные данные (`src/res/res_music.asm` — он больше не входит в сборку, остался
как документ) или формат потока.

```
node tools/snd_gen/snd_gen.js              # captured.json -> src/gen/snd_streams*.asm, проверка моделью
node tools/snd_gen/snd_gen.js --recapture  # заново снять captured.json с base_e2b8f32.rom (нужен /Users/boris/Projects/vector06js)
```

Если нотные данные правятся, сначала соберите ROM со старым драйвером из истории (коммит e2b8f32),
положите его как `base_e2b8f32.rom/.sym` (или смените имя в `capture.js`) и снимите заново.

Генератор падает, если модель проигрывателя на каком-нибудь тике расходится со съёмкой (проверяются оба
прогона с разными «чужими» периодами, чтобы отличить остаток периода прошлого звука от собственного).

## Что снимается и почему так

Состояние канала после тика = (включён?, делитель, период регистров AY как делитель). Делитель на порту
ВИ53 = `13P + P/2` для периода AY `P` — ровно то, что считал `vec_ay2vi`. Нота кодируется номером в таблице
делителей `vsn_div` (89 штук, индекс — 7 бит токена `ON`).

Остаток периода: кирка (`SFX_Picar`, A=0x45) раньше играла на периоде, который остался в регистрах AY от
прошлого звука на канале 3. Чтобы это поведение сохранилось, голос помнит делитель и при погашенном канале
(токены `PERIOD`, `ON_L`). Съёмка делается дважды с разными «чужими» периодами: если делитель отличается, звук
читает остаток, и в поток идёт `ON_L`.

Падение (A=1) — не данные: поток `[DW 1][ON d0][FALL]`, токен `FALL` каждый тик прибавляет к делителю 108 (период
+8; 12-битный период сворачивается на 0xD800).

## Зазор `.align`

Перед выровненными таблицами (`vec_rev4`) `mem_map.py` печатает «зазор N Б от .align». Нулевой зазор даёт
выигрыш в N байт образа. Чистые данные (потоки) можно унести за таблицы: перечислите их в `layout.json` так,
чтобы сумма размеров ≡ N (mod 256), перегенерируйте и пересоберите. Размеры потоков — в `snd_gen_stats.json`.
При любой правке кода до `.align` зазор меняется, подбор повторяют.
