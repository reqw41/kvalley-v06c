# Верификатор рекомпиляции Z80→i8080 (King's Valley)

Инструменты доказательства бит-в-бит эквивалентности MSX(Z80)-оригинала и
Vector(i8080)-рекомпилята, собранных из ОДНОГО исходника.

## Файлы
- `msx_headless.js` — headless-MSX: Z80-ядро (vector06js/Z80_v06.js) + мини-BIOS
  (WRTVDP/WRTVRM/RDVRM/WRTPSG/RDPSG/SNSMAT/RSLREG + ISR 0x38 → H.TIMI 0xFD9A),
  VDP-порты 98/99 → vram[], PSG, клавиатура (kbd[11]), hooks.onMemWrite.
  Грабли, уже съеденные: H.TIMI = 0xFD9A (C-BIOS!); ядро в im0 после RST теряет
  первый байт ISR (лечится бутстрапом IM 1); тела BIOS-стабов НЕ размещать в
  0x100-0x1FF (там точки RDVDP 0x13E / SNSMAT 0x141); psg[14]=0x3F (джойстик).
- `lockstep_kv.js` — локстеп: тик-в-тик (вход tickMain), сравнение MAP-префикса
  (одинаковая раскладка от GameStatus до stackArea) + VRAM-name против нашей
  тени; нормализация ROM-указателей через (символ,offset) по обоим .sym;
  честные точки сравнения — оба main в dummyLoop (idle).
- `repro_01_key_streams.json` — записанные потоки KeyHold/KeyTrigger репро
  «01»-бага (2843 записи, «01» на записи #2559).

## Использование
  node tools/verify/lockstep_kv.js kvm.rom kvm.sym kvv.rom kvv.sym [тиков]
(kvm.* — сборка без --target, kvv.* — с --target vector)

## Статус
- Заставка+меню+демо: 8000 тиков clean (MAP+VRAM).
- Живая игра со скриптованным вводом (смерти, туры): clean.
- «01»-баг: на Векторе воспроизводится (нож movKnife рисуется в r0c0-1 через
  drawTile при GS5); на MSX при bit-exact подмене KeyHold/KeyTrigger НЕ
  воспроизвёлся, НО полная сходимость маршрутов ещё не доказана: первый
  нелегальный дифф на записи #643 (+0x0 GameStatus m4/v1) — подозрение на
  сдвиг индексации записей или фазовый сдвиг заставки. TODO: счётчик честных
  сравнений в локстепе; выравнивание по GS-переходам.

## Юнит-тестирование рутин (unit_routine.js)
  node tools/verify/unit_routine.js kvm.rom kvm.sym kvv.rom kvv.sym <символ>
Прогоняет рутину на обоих ядрах со всеми DE-входами (CY=0), сравнивает HL.
ВАЖНО: тестовая RAM-область должна быть >=0xC000 — у headless-MSX зона
0x4000-0xBFFF защищена как ROM (unit_mueve.js наступил: «расхождения»
оказались заблокированными записями MSX-стороны).

Проверено чисто: coordVRAM_DE (все 65536 входов), mueveElemento (400
случайных структур+скоростей).

## Охота на «01»/нож (статус)
«01» в углу = ТАЙЛЫ НОЖА (movKnife -> drawTile). knife_exp.js (шумный,
среды не выровнены) показал РАЗНУЮ ФИЗИКУ ПОСАДКИ: MSX сажает нож на
Y=24 (кратно 8), Vector — на Y=20 (НЕ кратно!) => нож ложится/рисуется
в чужой ряд и след не стирается. Подозреваемые: knifeRebota/knifeCae
(статусы 7/8). СЛЕДУЮЩИЙ ШАГ: юнит AI_Cuchillos2 с согласованной
RAM-картой (MapaRAMRoot) на обоих таргетах, дифф трассы статусов/Y.

Гейт стартовой инициализации: сравнивать только при GS>=1 и tickInProgress==0
(стартовые заливки идут из MAIN и несравнимы). msx_headless: nameBase() по
VDP reg2 (стаб теперь хранит регистры).
ТЕКУЩИЙ ФАКТ (недожат): на входе полного тика 309 MAP бит-в-бит РАВЕН
(включая gameLogoCnt/waitCounter/timer), а VRAM-name РАЗЪЕХАЛСЯ ПО ФАЗЕ
АНИМАЦИИ: MSX рисует стадию меню на r19, Вектор ту же картинку УЖЕ поднял
на r4-6 (вектор ВПЕРЕДИ по отрисовке при равной логике!).
ГИПОТЕЗЫ СЛЕДУЮЩЕГО ЗАХОДА: (а) реентер tickMain у Вектора (несколько
логических стадий за один «полный тик» — проверить лог вызовов drawGameLogo
по тикам); (б) непрерывность VDP-указателя между тиками (vec_vdp_ptr vs
железный vaddr; кто-то из наших glue-путей двигает его между тиками).
Юниты ЧИСТЫ: coordVRAM_DE (65536), getMapOffset00 (16К), getMapOffset(+4,+8)
(8К), mueveElemento (400), chkKnifeChoca (тривиальна), knifeRebota
